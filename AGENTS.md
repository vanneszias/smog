# Development Guidelines

SMOG is a Bun + Turborepo monorepo: one Cloudflare Worker (`apps/site`, TanStack Start), one Expo app (`apps/mobile`), and everything else in `packages/*`. The design spec is `docs/superpowers/specs/2026-09-29-cloudflare-rewrite-design.md`; every non-trivial choice is recorded in `docs/DECISIONS.md`.

## Product terminology

SMOG means **Spreken Met Ondersteuning van Gebaren**: gestures support spoken communication. Keep this Dutch name in every language, with a translated explanation where helpful. Describe the content as SMOG gestures, not as learning a separate language. This applies to UI copy, metadata, email, code, comments, fixtures and documentation, including historical material. Translation overrides in D1 and cached mobile catalogues also need review when correcting deployed copy; changing the shipped catalogues alone does not replace an override.

### Brand voice and copy workflow

- The approved Dutch SMOG & Co tagline is **Mensen gaan van nature hun spraak ondersteunen met gebaren**. Preserve it exactly. English and French convey the same meaning; do not invent competing slogans. The expansion of SMOG explains the method and is not the tagline.
- Never use an em dash (U+2014) in any copy, including UI, metadata, email, documents and empty-value placeholders. Use a full stop, comma, colon or parentheses as the sentence needs; use a hyphen for an empty-value placeholder.
- Use the `copywriting` skill from `coreyhaines31/marketingskills` for all branding and copy changes. The shared installation is `~/.agents/skills/copywriting`; read its `SKILL.md` if the skill is not in the agent's catalogue. Read this section as the project's brand context before drafting. Project rules override the skill's generic defaults, including its allowance for occasional em dashes in long copy.
- Write in a warm, direct, accessible voice. Use concrete everyday situations and familiar words about speaking, gestures and learning. Help people find a gesture or prepare a lesson. Keep useful existing wording; avoid generic slogans, inflated promises, invented evidence and pressure to convert. Ask the owner for feedback before changing the tagline or brand positioning.
- Videos are a memory aid alongside a SMOG course or initiation, not a standalone course. Use this positioning on both home screens, in discovery copy and in video notices. Keep course links descriptive rather than "click here".
- Promise no fixed sponsorship review deadline. Explain that the sponsorship is checked before publication and the sponsor receives an email when it is online. Names and optional logos appear over the gesture's own video; expiry removes that end card, not the gesture video.

## Commands

### Root Commands
```bash
bun install                  # Install (hoisted linker, see bunfig.toml)
bun dev                      # Start all dev servers (turbo)
bun run build                # Build all packages
bun run check                # Biome lint + format with auto-fix
bun run check:ci             # Biome in CI mode (no writes)
bun run check-types          # Typecheck all packages (turbo check-types)
bun run test                 # All non-browser suites in packages/testing (including repository/document guards)
bun run test:feature lessons # One feature across web, services and native; --include-e2e adds browser tests; --list previews discovery
bun run test:e2e [-- --project public|a11y|a11y-signed-in|a11y-reflow|admin|admin-a11y|serial]  # Playwright e2e (apps/site): the seven projects one after another, each wrapped by test-deadline; --project runs one (a CI shard). Fresh D1 first (see Local auth); E2E_PORT / E2E_MUX_PORT / E2E_MOLLIE_PORT move the ports
bun run knip                 # Unused files, exports and dependencies
bun run boundaries           # Enforce the package dependency graph
bun run audit                # bun audit: all dependencies, no advisory ignores
bun run mobile:release-check # expo-doctor + expo export (iOS + Android) + bundle size
bun run release:check        # Everything CI runs, in order
SMOG_OFFLINE=1 bun run release:check  # Same, on a machine without internet access
bun run admin:grant --env <dev|staging|production> [--create [--yes]] [--dry-run] <email>  # Give an account the admin role and lift any ban; --create first inserts a verified, password-less admin when none has that email (staging/production need --yes) (dev: local D1, else remote)
bun run maintenance --env <dev|staging|production> on|off [--message …] [--until ISO] [--dry-run] [--yes]  # Maintenance mode (KV; production needs --yes)
bun run cron <expiry|reminders|stale|retention>  # Run one Cron Trigger on the local dev server
bun run retention --env <dev|staging|production> --dry-run  # Count what the daily purge would delete (read-only D1 SELECT)
bun scripts/ensure-cloudflare-resources.ts --env <staging|production> --check|--create|--dry-run  # Queues, DLQs, R2 bucket + CORS (the deploy job runs it)
bun scripts/check-deploy-config.ts --env <staging|production> [--offline] [--warn-only]  # Vars, SITE_URL, KV/D1 ids in wrangler.jsonc, and (online) `wrangler secret list` against REQUIRED_WORKER_CONFIG[env] + provider pairs; --warn-only is staging only (the deploy job runs it first)
bun run migrate:convex <plan|apply|mux scan|mux renditions|we-moved|help> …  # The Convex → D1 importer (@smog/migrate-convex); every path option is absolute; `mux renditions` and `we-moved` are dry without `--apply`, `apply` only with `--dry-run` (production needs `--yes`); `apply --reset-only` (dev, staging) removes what a plan imported and applies nothing (a second run removes 0), `we-moved --resend <ids-file>|--failed` replays failed batches (docs/cutover-runbook.md)
```

Setup of the accounts, secrets and stores is `docs/deployment.md`; the production switch-over (the domain decision, the Convex import timeline, the rollback) is `docs/cutover-runbook.md`; the owner's ordered list is in `docs/PROGRESS.md` (Owner actions in order).

`release:check` runs three scripts sequentially locally. CI (`.github/workflows/ci.yml`) has **four jobs**: the three lanes below (`Release check (core)`, `(tests)`, `(mobile)`, the same scripts on separate runners with `fail-fast: false`) and the `e2e` job, which is not part of `release:check`, so a green `release:check` does not say the e2e passed. The lanes: `release:check:core` (`check:ci` → `boundaries` → `scripts/release-config-check.ts` → `check-types` → `build` → staging `deploy:dry` (offline: the staging build, the deploy guard, `wrangler deploy --dry-run`) → `scripts/check-deploy-config.ts --env staging --offline` → `knip` → `audit`), `release:check:tests` (all tests), `release:check:mobile` (online expo-doctor, both iOS/Android exports, bundle sizes and gallery checks). There is no render lane any more: the Remotion render pipeline, its container image and its CI lane were removed in phase 10b task 9. The **`e2e` job** (always on, no `needs`, in parallel with those three lanes; Deploy's reusable call of `ci.yml` waits for it) is a matrix of seven shards, one Playwright project each on its own runner: `public` (every spec not matched below), `a11y` (every `a11y-*.spec.ts` the next two do not name: axe over the guest routes, overlays and banners), `a11y-signed-in` (`a11y-signed-in` and `a11y-keyboard`), `a11y-reflow` (`a11y-reflow` and `a11y-landmarks`), `admin` (`admin-*.spec.ts` except the next ones), `admin-a11y` (`admin-*a11y*.spec.ts`: axe over every admin screen, split off to keep each shard under 15 minutes) and `serial` (`admin-catalog`, `admin-languages` (adds a language to the menu) then `admin-settings`, the maintenance window, on one worker). The projects are independent (no `dependencies`); CI installs the Chromium this Playwright expects (`playwright install --with-deps chromium`, cached by version), runs `retries: 1` with traces on the retry, and `packages/testing/e2e-flaky-report.ts` turns a pass-on-retry into a `::warning::` and a job-summary row (a bug to fix). No `waitForTimeout` in `packages/testing/e2e` (a guard test). Deploy waits for every lane. Pushes to `develop`/`master` run the gate through Deploy only; other branch pushes and pull requests run CI directly.

`SMOG_OFFLINE=1` only affects expo-doctor, and the result is **not equivalent to CI**. Offline, three doctor checks are degraded (the script prints this list every time): the config schema check is tolerated when the schema fetch crashes; the SDK dependency-version check only compares against the bundled native-module list, so the api.expo.dev pins (react, react-native, typescript, jest-expo, …) go unchecked; and the React Native Directory check is off. Fetch failures are warnings (`EXPO_DOCTOR_WARN_ON_NETWORK_ERRORS=1`). Every other doctor failure still fails. Never set it in CI; CI is the authority. The same gap, beyond doctor: `bun run audit` needs the advisory registry (a new advisory fails CI while an offline run is green) and `release:check` never runs the e2e job (`bun run test:e2e`, below). A release check that exits 0 on a machine without network therefore proves the core, tests and mobile lanes minus those parts; say which parts you could not run.

Deploys run from `.github/workflows/deploy.yml` on pushes to `develop` (staging) and `master` (production). It first runs `ci.yml` (reusable, `workflow_call`) as the `release-check` job; `deploy` needs it. Then, in this order: `scripts/check-deploy-config.ts` (below), `scripts/ensure-cloudflare-resources.ts` (staging `--create`; production `--check` unless the repository variable `SMOG_PROVISION_PRODUCTION` is `1`; it never changes or deletes what exists), D1 migrations (`packages/db/migrations/*.sql`), then `CLOUDFLARE_ENV=<env> bun -F @smog/site deploy`. Without the `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` secrets a staging deploy skips every step with a warning (green, nothing deployed) and a production deploy fails at its first step. The resources step needs, on the account and token: the Workers Paid plan (Queues), R2 enabled on the account, and the token permissions Workers R2 Storage: Edit and Workers Scripts: Edit (or Queues: Edit); a refusal prints a `[provision]` line naming the missing one. A bucket CORS that does not allow the PUT from `SITE_URL` fails the step with the `wrangler r2 bucket cors set` command to run by hand (it is never overwritten). Both the check and the resources step refuse a **placeholder origin**: a `SITE_URL` that is not a bare `https:` origin, a reserved host, or a workers.dev host without four labels (`<script>.<subdomain>.workers.dev`; staging is `smog-site-staging.zias.workers.dev`, production `smog-site-production.zias.workers.dev` by default, the domain `app.smog.vlaanderen` being the owner's choice in `docs/cutover-runbook.md`).

**The deploy config check** (`scripts/check-deploy-config.ts --env <staging|production> [--offline] [--warn-only]`, phase 8 ruling 1) holds an env to `REQUIRED_WORKER_CONFIG[env]` (`@smog/config/env/worker`): the required vars non-empty in `wrangler.jsonc`, `SITE_URL`, the exact KV and D1 placeholder ids refused, and, online, every required secret in `wrangler secret list --env <env>` (each error prints its `wrangler secret put` line; the first `secret put` creates the Worker, so `secret list` fails until then; the token needs Workers Scripts: Read, which Edit includes). Sign-in providers are all-or-nothing pairs (`PROVIDER_SECRET_GROUPS`: Google two secrets, Apple three); an absent provider or OpenPanel pair is only listed as recommended. **`SMOG_REQUIRE_SECRETS`**: staging only warns (`--warn-only`, which also turns a crashed script or a hung `wrangler` into a `::warning::`) until the owner sets `SMOG_REQUIRE_SECRETS=1` as a variable of the **`staging` GitHub environment** (not the repository: a repository-level 1 also makes staging enforce, and production ignores it). **Production always enforces and refuses `--warn-only`.** `release:check:core` runs `--env staging --offline` (no secrets).

**The render pipeline is retired** (phase 10b task 9, owner-confirmed 2026-10-23). A sponsor's name and logo are an end card over the gesture's own video (`SponsorEndCard`), so nothing is rendered: `wrangler.jsonc` has no `workflows`, `containers`, Durable Object binding, migration or `RENDER_MODE`, and the deploy guard (`apps/site/scripts/deploy-guard.ts`) fails a build that has any of them or bundles Remotion or mediabunny. A sponsorship still in `rendering` or `render_failed` (an old row) is moved to `in_review` by the hourly stale cron (`retireRenderStates` in `@smog/sponsorships/server`, a `render_succeeded` trail event with `retired: true`), where an admin approves or rejects it. The statuses, events and columns stay (migrations are append-only); the details are `docs/DECISIONS.md`, "Retire the render pipeline (phase 10b task 9)".

All automated tests, fixtures, fakes, runner configs and test-only dependencies live in the private `@smog/testing` workspace (`packages/testing/README.md`). Group by runtime, then feature; cross-cutting coverage goes in `shared`. Package `test` scripts are thin forwards to `packages/testing/runner.ts`; production packages cannot depend on the testing workspace. Its discovery and source-separation guards fail on unowned or ambiguous tests and tests/support imports in production trees. Feature runs do not replace the full cross-cutting release gate.

Every runner invocation goes through `bun <root>/packages/testing/deadline.ts -- <command>`: after 25 minutes (`SMOG_TEST_DEADLINE_MINUTES`) it prints `Test command hung` with the process tree and Node reports, kills the command's process group and exits 124; a command that exits 75 (a stuck Vitest pool, see `StallReporter`) runs once more. `bun run test` streams the isolated suites sequentially, without cached passes. The Workers-pool Vitest configs spread `WORKERS_POOL_TEST_OPTIONS` from `packages/testing/support/config/vitest.ts` (timeouts, `verbose` in CI, `[vitest-stall]` reports). Keep deadlines per runner/shard, never around a full seven-shard E2E run.

Use `bun run <script>` for scripts whose name clashes with a Bun built-in (`build`, `test`).

### Site (TanStack Start on Cloudflare Workers)
```bash
bun -F @smog/site dev        # Vite dev server with local bindings (port 5173)
bun -F @smog/site build      # Build (env.dev; deploy builds set CLOUDFLARE_ENV=staging|production)
bun -F @smog/site deploy:dry # Build for staging, run the deploy guard, wrangler deploy --dry-run
# Deploys: CLOUDFLARE_ENV=staging|production bun -F @smog/site deploy (never bare `wrangler deploy`; it builds the workspace packages through turbo first)
bun -F @smog/site test       # Vitest (Workers pool)
bun -F @smog/site check-types
bun -F @smog/site cf-typegen # Generate worker-configuration.d.ts (gitignored; check-types does it too)
```

Local auth (dev only): copy `apps/site/.dev.vars.example` to `.dev.vars` (it has a dev `BETTER_AUTH_SECRET`), then `bun -F @smog/db migrate:dev && bun -F @smog/db seed:dev`. The seeded admin is `admin@smog.test` with the **dev-only** password `smog-dev-admin`. Emails are not sent in dev: read them at `http://localhost:5173/dev/mail` (or `/dev/mail.json`). Migrations are append-only from now on: never edit an existing migration; add a new one (`bun -F @smog/db db:generate`). To start the local D1 from scratch, `rm -rf apps/site/.wrangler/state/v3/d1` first. **The next free migration number is 0029** (0013 `dead_letter` and the `audit_log` rebuild, 0014 the `sponsorship.logo_key` index, 0015 to 0023 the phase 10b data foundations: `language`, `ui_string`, translations, audio, legal texts, `user_role`, `needs_recut`, `gesture_fts.locale`, audit kinds, 0024 to 0027 the phase 10c lessons data: `gesture_teacher_info`, `gesture_drawing`, `lesson*`, audit kinds; a rebuild of a table that other tables reference must back up and restore them, see `docs/DATA_MODEL.md`); `packages/testing/bun/shared/tooling/docs-check.test.ts` fails when a document says another number.

**E2E locally, the way CI runs it:** one project at a time on a fresh D1 (`rm -rf apps/site/.wrangler/state/v3/d1 && bun -F @smog/db migrate:dev && bun -F @smog/db seed:dev`), with `CI=1 PLAYWRIGHT_CHROMIUM_PATH=<Playwright's chromium_headless_shell> taskset -c 0,1 bunx playwright test --project=<name>` from `apps/site` (full Chrome and more CPUs hid failures that only CI showed). A new spec goes into the project whose filename pattern in `packages/testing/config/playwright.ts` matches and must keep its shard well under 15 minutes on CI (observed CI times: `public` ~10 min, `admin-a11y` ~9.5, `admin` ~5, `a11y-reflow` ~4.5, `a11y` ~4, `a11y-signed-in` ~3, `serial` ~3). A test that passes only on the retry is a bug (`packages/testing/e2e-flaky-report.ts` says so in CI).

Turnstile: `TURNSTILE_SITE_KEY` is a public var in `wrangler.jsonc` (`env.<env>.vars`) and `TURNSTILE_SECRET_KEY` a secret (`wrangler secret put`). Both are required in production before launch: without the site key the web shows no widget and email sign-up, sign-in, reset, code and magic-link requests fail. Staging uses Cloudflare's always-pass test keys; dev needs neither.

Security headers and the CSP come from `apps/site/src/worker/headers.ts`, on every Worker response. The CSP is enforced in dev and production and `Report-Only` in staging. Inline scripts need Start's per-request nonce (automatic for anything Start renders) or a build-time hash (the theme script). The CSP ends with `report-uri /api/csp-report; report-to csp`, and documents get `Reporting-Endpoints: csp="<request origin>/api/csp-report"` in every env. `POST /api/csp-report` (`apps/site/src/server/csp-report.ts`) takes `application/csp-report` and `application/reports+json` (16 KiB cap, rate-limited on `RL_ANALYTICS` as `csp:<ip>`, 204, exempt from maintenance, no Origin check and no CORS) and logs one `[csp] violation {…}` line with every URL reduced to origin plus path (re-edit and renewal URLs carry raw tokens); it never relays to OpenPanel. On staging the reports reach the Worker only once Cloudflare Access bypasses `/api/csp-report`. A route that sets its own `Content-Security-Policy` keeps it; any other header the route set is kept too. Maintenance mode is the KV key `maintenance` (`maintenanceSettingSchema` in `@smog/config/maintenance`, re-exported by `@smog/admin/schema`; toggled at `/admin/settings` or with `bun run maintenance`; `on` keeps the bypass version, `off` starts a new one). During a window `/sign-in` and only the admin sign-in routes of `/api/auth` (`AUTH_SIGN_IN_ROUTES` in `apps/site/src/worker/maintenance.ts`, served by a sign-in-only Better Auth that creates no user) stay open; a signed-in admin gets past the rest with `POST /api/maintenance/bypass` (12 h cookie, valid until the window ends). A change reaches every visitor within about 2 minutes (isolate cache, KV edge cache, KV propagation).

**Guards that fail a change on purpose (phase 9).** Each is a test; extend its table in the same commit as the change it guards.
- **Authorization:** `packages/testing/workers/shared/api/service/authz.test.ts` lists every oRPC procedure with who may call it (a new procedure without a row fails), and `packages/testing/workers/auth/site/security-authz.test.ts` runs banned and cross-user calls through the whole stack.
- **Routes and rate limits:** `packages/testing/bun/shared/tooling/security-guard.test.ts` needs one row per route file (its limiter, or "none" with a reason; the table is printed in `docs/API.md`) and scans the sources for logged secrets. `POST /api/rpc` and `/api/openapi` refuse a body over 5 MiB (`RPC_MAX_BODY_BYTES`); the `[csp] violation` log is sampled (20 lines a minute per isolate); `apps/site/src/worker/top-level.ts` logs one redacted `[error]` line per unhandled fetch, queue or scheduled error.
- **Tokens stay in the URL fragment:** a sponsor re-edit or renewal link is `/sponsor/edit#token=…` or `/sponsor/renew#token=…`, built only by `sponsorshipLinkUrl` (`@smog/sponsorships/schema`) and read after hydration (`useLinkToken`); never put a token in a query string. Old `?token=` links are moved by the client and by the legacy 302 (`Cache-Control: no-store`). `packages/testing/bun/shared/site-scripts/token-links.test.ts` fails on any other form.
- **Performance budgets:** `apps/site/perf-budget.json` holds a gzip budget per route entry (the entry plus its static closure) and the Worker cap; `bun run build` (the deploy guard with `--bundle`) fails over a budget, for a route chunk with no entry (`dev/*` is exempt) and for a source map. **A new route needs a budget entry**; a lazy split lowers the budgets in the same commit (the 200/300 kB targets are not met yet, `docs/DECISIONS.md`, phase 9 task 6). Query plans of the hot D1 paths are tested with `fullScans` from `packages/testing/support/db/plan.ts`: a full scan fails unless it is named in the test.
- **Cache policy:** one table in `apps/site/src/worker/cache.ts` (HTML `private, no-cache`; API, `/_serverFn/` and auth `no-store`; hashed assets immutable through `apps/site/public/_headers`, which matches by extension, so a new hashed extension needs a line there). `_headers` also carries Permissions-Policy, COOP and HSTS for static files, which never reach the Worker.
- **The documents:** `packages/testing/bun/shared/tooling/docs-check.test.ts` (in `bun run test`) fails when AGENTS.md, README.md or `docs/*.md` name a `bun run` script, a path, a relative link, a `docs/DECISIONS.md` section title or a next free migration number that does not exist, or when the CI lanes and e2e shards listed here differ from `ci.yml`. A path that is gitignored is accepted; any other exception goes in `PATH_ALLOW` with its reason.

**Dead letters (phase 9).** Both queue DLQs (`smog-<env>-email-dlq`, `smog-<env>-sponsorship-events-dlq`) have a push consumer (`apps/site/src/worker/dlq-queue.ts`, `max_retries` 20, `retry_delay` 300) that stores each message in D1 `dead_letter` (migration 0013) and keeps it 14 days (daily retention). The admin screen `/admin/dead-letters` lists, **replays** and **discards** (audited); the dashboard shows the open count and the daily retention cron sends one `admin_dead_letter` digest email per admin. Messages that carry a secret (the four auth emails and the renewal reminder, `@smog/email/body-policy`), key-less and invalid ones are stored **without a body** and cannot be replayed; an account deletion erases rows by recipient. Alerts for this are the digest and the Cloudflare notifications the owner sets up (`docs/deployment.md` §8a, `docs/PROGRESS.md` owner step 2).

## UI kit (phase 10a)

The look is one token set (`packages/styles/src/tokens.ts`, generated into `packages/styles/generated/*` by `bun -F @smog/styles generate`) used by two kits with the same component names: `@smog/ui-web` (Tailwind 4, shadcn `radix-maia` components, `API.md` lists every component) and `@smog/ui-native` (NativeWind 4 on Tailwind 3, the same names and props, `API.md`). Screens in `apps/*` import from the kit and write classes from the vocabulary below; the guards are tests.

- **Vocabulary.** shadcn's semantic roles: `background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, `sidebar-*`, `chart-1..5`, each with `-foreground`. SMOG's own: `highlight` (the orange; shadcn's `accent` is a quiet green tint), `primary-strong` (deeper green for text on warm neutrals), `success`, `warning` and `danger` `-strong` / `-subtle` (`danger-strong` and `danger-subtle` keep their names; plain `danger` is `destructive`), `surface-sunken`, `border-subtle`. The phase 1 to 9 names `surface`, `surface-raised`, `danger`, `foreground-muted` and `focus-ring` are gone (a Tailwind class on one builds no CSS, silently): `packages/testing/bun/shared/site-scripts/retired-tokens.test.ts` and both `classes.test.ts` fail on them. No hex colours or arbitrary values in the mobile app (a source guard). Every pair that carries text is in `packages/styles/src/contrast.ts` (AA body, 3:1 UI) and tested; a new pair goes there first.
- **Green is a surface.** `bg-primary text-primary-foreground` (the filled green: hero, auth) and `bg-sidebar text-sidebar-foreground` (the deeper green: the site header, the admin sidebar, the native stack headers). On native, `Surface` (`tone="primary" | "header"`) gives `Text`, `Heading`, `Button`, `IconButton` and `FavoriteButton` their on-green colours; overlays put the page back with `SurfaceReset`. On the web the header's controls use `apps/site/src/components/app-shell/on-green.ts`.
- **Tailwind's default scales are back** (web and native), so registry code compiles unchanged; only `touch` (44 px), the named type steps (`text-body`, `text-title-1`, ...), `shadow-0|1|2` and the semantic colours are SMOG's. The 44 px target, the 2 px focus ring, reduced motion and the i18n names stay kit contracts, edited into each ported component.
- **Font: Figtree.** Web: the variable woff2 (Latin and Latin Extended) in `apps/site/src/fonts/` is hashed by Vite into `/assets`, preloaded from the root route, `font-display: swap`, with the size-adjusted `Figtree Fallback` (no layout shift; the CLS spec guards it). Native: four TTFs in `apps/mobile/assets/fonts`, embedded by the `expo-font` plugin (`apps/mobile/app.config.ts`); use `font-regular|medium|semibold|bold` (one file per weight). Email keeps the system stack. Updating the font: `docs/DECISIONS.md`, "Ruling 7, Figtree".
- **Embedding a font changes the native fingerprint.** The next mobile build after phase 10a must be a native (EAS build), not an OTA `eas update`: an OTA cannot reach the older binaries (`docs/PROGRESS.md`, owner actions).
- **Heavy blocks are lazy.** `@smog/ui-web/command` (cmdk) and `@smog/ui-web/carousel` (embla) are separate entry points loaded with `lazy(() => import(...))`; the search palette and the admin chart are their own chunks. `@smog/ui-web` sets `"sideEffects": false`; without it the barrel keeps every component in every chunk. Budgets are in `apps/site/perf-budget.json` (`bun run build` fails over one).
- **Updating or adding a shadcn component: by hand, from the pin.** The registry (`ui.shadcn.com`) answers 403 from the sandbox, so **the shadcn CLI could not be used and was never run**: components were ported by hand from a checkout of `github.com/shadcn-ui/ui` at the pinned commit `ba1503c64472b82256d9de95e2e62c5901a38e8b` (`apps/v4/registry/bases/radix/ui/*.tsx`, style `radix-maia`; the pin is recorded only in `docs/DECISIONS.md`, "shadcn init" and "Ruling 3", nothing is vendored). To port one: shallow-clone the repo at the pin (or at a newer commit, recorded in DECISIONS), read the component, resolve each `cn-*` placeholder class to its `@apply` list in the style file `style-maia.css` of the checkout (a marker without a rule is dropped), swap the icons for `lucide-react`, rewrite imports to `../lib/cn` and relative paths (the site's `@` alias is the site's `src`, not the kit's), then edit for the kit contracts (44 px, focus ring, reduced motion, `className` merged last, React 19 `ref` prop, i18n names from `@smog/i18n`), add it to `src/index.ts`, `API.md`, the gallery (`/dev/ui`, `apps/site/src/dev/ui-gallery*.tsx`) and a test, and give `ui-native` a counterpart or a `WEB_ONLY` reason in `packages/testing/native/shared/ui-native/contract.test.tsx`. If the CLI becomes reachable it is a conscious update recorded in DECISIONS; discard its edits to `src/styles.css` and make its `@/` imports relative. `packages/ui-web/components.json` holds the config.
- **Screenshots.** The repo commits no screenshot baselines and nothing is compared with one: the screenshot specs only write review PNGs when a directory variable is set (`PUBLIC_SHOTS_DIR`, `ADMIN_SHOTS_DIR`, `SPONSOR_SHOTS_DIR`; full page, light and dark at 390 and 1280). Regenerate them for a visual review, do not invent baselines. Visual state of a mobile change is not testable here: it needs a device pass (`docs/PROGRESS.md`).

## Translations and languages (phase 10b)

Every visible text can be translated without a deploy. The design is `docs/superpowers/specs/2026-10-22-phase-10b-i18n.md`; the decisions are in `docs/DECISIONS.md` (the `phase 10b` sections).

- **Languages are data.** The `language` table (code, own name, `Intl` tag, order, enabled, one default; `nl`, `en`, `fr` seeded, `nl` the default) is the menu, the cookie check and the foreign key of `user.locale` and `sponsor.locale`. `Locale` is a `string` (`ShippedLocale` is the union of the three bundled catalogues). Only enabled languages are accepted at the edges (`resolveLocale`, the `setLocale` cookie write, the RPC context, `account.updateProfile`, checkout); a language is never deleted, only disabled. Code that takes a language checks it against the table, never against `LOCALES`.
- **The text layers and the fallback chain.** (1) The shipped base: `packages/i18n/src/locales/{nl,en,fr}.json`, one catalogue per language, parity tested (`catalog.test.ts`). (2) The `ui_string` overlay in D1 (`locale`, `key`, `value`, `source_hash`), written by translators. (3) The KV key `i18n:version`, bumped by every write that must show at once (isolates memoise 30 s, so an edit reaches everyone within about two minutes; the writing isolate sees it immediately). A key resolves: overlay of the language, shipped text of the language, overlay of the default language, shipped default text; never an empty string or the key name (`returnEmptyString: false`). A language with no shipped catalogue is its overlay over `nl`. `@smog/i18n/server` loads it (`loadCatalogue`, `loadLanguages`, `loadLegalText`) and falls back to the shipped texts when KV or D1 fails; the maintenance page keeps the shipped three on purpose. The mobile app gets the same through the public `system.i18n` procedure (cached offline, the bundle as base).
- **One catalogue chunk per language on the web.** The client build resolves `@smog/i18n` to `index.lazy.ts` (no catalogues in the entry); `src/client.tsx` awaits the `<html lang>` catalogue before hydrating and the root loader awaits `ensureCatalogues(locale)`. Code that translates with `lng:` into another language than the active one (the legal pages and editor) must load that catalogue plus `nl` itself. `perf-budget.ts` counts the largest catalogue chunk in every entry. A new key goes into all three shipped files (parity test; French wants U+00A0 before `:` and U+202F before `?`, a typography test; a JSON rewriter that decodes the escapes rewrites the whole file).
- **Roles are a set.** `user_role` (`translator`, `teacher`, `admin`; `user.role` is mirrored by triggers) and `session.user.roles` (read on every request, so a grant or demotion applies at once). Guards: `requireRole(...roles)` and `translatorProcedure` / `teacherProcedure` / `adminProcedure` in `@smog/rpc`; an admin passes every role check. Admins grant and revoke on the user screen (`users.grantRole`, `users.revokeRole`; never the last admin, never on yourself); `bun run admin:grant` also writes the `user_role` row. The site gate lets a translator into `/admin`, narrowed to the translation screens; every procedure refuses again on its own (`packages/testing/workers/shared/api/service/authz.test.ts`, `packages/testing/workers/translation/site/security-authz-translation.test.ts`).
- **The translation admin** (`@smog/translation`, `/admin/translation/*`): the strings table (server-paged, filters missing, stale and invalid, optimistic save with a `CONFLICT` choice, revert to the shipped text), import and export (JSON flat or per language, CSV with BOM and CRLF; a dry run first; bad rows are skipped, not applied), coverage per language, the languages screen (admin), the legal texts and the audio. Gestures and categories have a tab per language on their editors (`catalogTranslation.*`); a translation falls back to the default language per field and `fallbackUsed` says so. Search runs per language (`gesture_fts.locale`, the default row for an untranslated gesture; the typo tier is a per-language projection). Every write is audited in the same D1 batch (`translation.*`, `language.*`, `legal.*`); an audit entry carries keys and counts, never a text.
- **Legal texts are D1 rows** (`legal_text`, versioned, one draft per kind and language, six published version-1 rows seeded from the shipped texts). `/privacy` and `/terms` read the highest published row, validated (`validateLegalDocument`), and fall back to the shipped text, then to Dutch. **A translator can publish** (risk R1, accepted by the owner in `docs/LEGAL-SIGNOFF.md`, item 9); restore is admin only; a publish never re-asks consent (`CONSENT_POLICY_VERSION` stays a code constant).
- **Audio and the name overlay.** A teacher or translator uploads a clip per gesture and language (`translation.uploadAudio` presigned R2 PUT or the signed `PUT /api/audio/upload/...` fallback, then `finalizeAudio`, which checks the MP3 or M4A bytes, at most 10 s and 1 MiB, copies to a fresh key and audits). `GET /api/audio/<gestureId>/<locale>/<uuid>` is public, immutable and supports Range. Videos are cut without the name; the player draws the name as an overlay (`VideoPlayer nameOverlay`, `preferences.hideGestureName`). Every existing video still has the name burned in (`gesture.needs_recut = 1`) until someone re-cuts it and presses "textless uploaded" (`gestures.recutDone`); a new upload sets it to 0 (`textless`). Native audio is `expo-audio`, a native module (see `docs/PROGRESS.md`).
- **The sponsor end card.** No video is rendered any more: a paid sponsorship goes `in_review`, then `live`, and the player shows the sponsor's name and logo (`GET /api/sponsor-logos/<uuid>`, running sponsorships only) over the last 4 seconds of the gesture's own video (`@smog/utils` `endCardStart`). Old `rendering` and `render_failed` rows are moved to `in_review` by the hourly stale cron.
- **Adding a language, end to end.** (1) An admin adds it at `/admin/translation/languages` (a canonical code such as `pt-BR`, its own name, an `Intl`-valid tag); it shows in the menu at once with the default text and 0 % coverage. (2) Translators fill the strings at `/admin/translation/strings` (or export, translate and import a CSV), then the gesture and category tabs, the legal texts and the audio. (3) A translator or admin publishes the legal texts. (4) Nothing to deploy. A shipped catalogue (`packages/i18n/src/locales/<code>.json`) is only for a language the app must have offline from the first launch: add the file, register it in `shipped.ts` and `LOCALES`, and keep parity with `nl`. Plural forms are ordinary keys; the language needs every CLDR category it uses (`pluralProblems`).

## Lessons and teacher PDFs (phase 10c)

A teacher or admin enters private teaching information and drawings per gesture, builds lessons and downloads a PDF for teachers or for participants in a language; the mobile app lists and shares them. The spec is `docs/superpowers/specs/2026-10-23-phase-10c-lessons.md`, the plan `docs/superpowers/plans/2026-10-23-phase-10c-lessons.md`; the decisions are in `docs/DECISIONS.md` (the `phase 10c` sections, ending with the close-out). No binding, queue, cron or var was added: the built staging `wrangler.json` did not change.

- **Two packages.** `@smog/lessons` (`packages/features/lessons`, a feature package with `./schema`, `./contract`, `./server`, `./client`) owns teacher info, drawings, lessons and the export (plan, cache, limits). `@smog/pdf` (`packages/pdf`) is the pure layout engine: a validated document description and assets in, `Uint8Array` out (`pdf-lib` + `@pdf-lib/fontkit`; no D1, R2, `Bun.*`, `node:*` or `cloudflare:*`, so it runs in tests, the Worker and, if risk R1 ever forces it, a browser). Only `@smog/lessons` and the site depend on `@smog/pdf` (`@smog/config/boundaries`). Figtree Regular and Bold and the logo are in `packages/pdf/assets`, loaded by the site as `?bytes` modules (`apps/site/build-bytes.ts`). `pdf-lib` and fontkit are unmaintained since 2022; the maintained fork `@cantoo/pdf-lib` can replace them behind the package's API (`docs/DECISIONS.md`, task 1).
- **Teacher data is private data.** `gesture_teacher_info`, `gesture_drawing` and the lesson tables are read only by `@smog/lessons/server`; a teacher field or a drawing key never appears in a public output, query, search index, cache key, sitemap or log. Guards, all tests: `packages/testing/workers/shared/api/service/teacher-privacy.test.ts` (every output schema outside `teacher` and `lessons`), `packages/testing/workers/gestures/service/teacher-privacy.test.ts` (public queries and the search index), `packages/testing/bun/shared/tooling/teacher-privacy-guard.test.ts` (a source scan; a new place that may name a teaching field goes into its `ALLOWED` list with a reason). Every procedure has a row in `packages/testing/workers/shared/api/service/authz.test.ts` (levels `teaching` for teacher, translator and admin; `teacher` for lessons) and a banned and cross-role case in `packages/testing/workers/lessons/site/security-authz-teacher.test.ts` and `security-authz-lessons.test.ts`. Audit entries (`teacher.*`, `lesson.*`) carry ids, field names and counts, never a text.
- **Roles.** A teacher or admin writes teacher info in any language; a translator only in non-default languages and never drawings; lessons and PDFs are teacher and admin only. `/admin` admits a teacher to `/admin/lessons` and `/admin/teacher-info/<id>`.
- **Drawings.** PNG or JPEG only, at most 512 KiB and 1,200 px (`DRAWING_UPLOAD_*` in `@smog/db/enums`; the table CHECKs stay looser, WebP cannot be embedded), checked by their bytes (header, CRC, a decompression-bomb check), presigned PUT or the signed same-origin fallback, then `finalizeDrawing` copies to a fresh key. They are served only by the private route `GET /api/teacher/drawings/<gestureId>/<step>` (teacher, translator or admin; `private, no-cache`, never a public URL or CDN cache). A daily sweep deletes orphan objects under `teacher/drawings/` after 24 hours.
- **Lessons API.** The `lessons` router (`lessonProcedure`, teacher or admin): list (keyset), get, create, update (the whole lesson with its version: `CONFLICT` on a stale one; the builder autosaves), duplicate, delete, readiness and `exportPreview`. A lesson is editable by its author; any teacher reads and can copy it. Reference: `docs/API.md`.
- **The PDF route and its cache.** `GET /api/teacher/lessons/<lessonId>/pdf?template=teachers|participants&locale=` (teacher or admin, `RL_API` per IP, a render limited per user on `RL_SPONSOR`; at most 150 gestures for teachers and 80 for participants, 15 MiB, a 25 s budget; typed JSON errors). The file is cached in R2 at `teacher/pdf/<lessonId>/<fingerprint>-<template>-<locale>.pdf`; the fingerprint is a hash of `LESSON_PDF_LAYOUT_VERSION`, `lesson.version` and, per gesture, its teacher-info versions, drawing ids and name `updated_at`, so a stale file is never matched; the daily retention deletes `teacher/pdf/` objects older than 30 days.
- **Bumping `LESSON_PDF_LAYOUT_VERSION`.** Whenever the engine's print changes (any non-test file of `packages/pdf/src`, the fonts, the logo, or the `pdf-lib` or fontkit version), `packages/testing/bun/shared/tooling/lesson-pdf-version.test.ts` fails and prints the version to set and the entry to add: raise the constant in `packages/features/lessons/src/server/layout-version.ts` and add the new hash to `LESSON_PDF_ENGINE_HASHES` (add, never overwrite an entry). A change that does not alter the printed file still needs the bump; a spare cache miss is cheap.
- **Deploy guard (`apps/site/scripts/deploy-guard.ts`, tests in `deploy-guard-pdf.test.ts`).** A build fails when a browser file contains a `pdf-lib` or fontkit marker, when any file contains an `unpdf` (PDF.js) marker (`unpdf` is a test-only devDependency of `@smog/pdf`), or when a file imports the engine's chunk statically (the export loads it with `import("@smog/pdf")` only, so it never reaches a client entry or the Worker's startup).
- **Sample PDFs.** `bun packages/testing/samples/lesson-pdf.ts <absolute directory>` writes a teachers' and a participants' sample from invented fixtures (`packages/testing/support/pdf/fixtures`) for visual review; nothing is compared with a baseline.
- **Mobile.** Settings, "Lessons" (teacher or admin by `session.user.roles`; the server decides again): a lesson list, a read-only lesson and "Export as PDF" through the same route to the share sheet (`fetch` with the session cookie, a typed refusal per code). Read procedures only; lessons are never written to the offline cache and the PDF file is swept like the account export. The sheet reuses the web dialog's `admin.lessons.export.*` strings.
- **Migrations.** 0024 to 0027 (teacher info, drawings, the lesson tables, the `audit_log` rebuild), 0028 (legal text version 2, the corrected privacy and terms); **the next free number is 0029** (the number stays in the Development section above; `packages/testing/bun/shared/tooling/docs-check.test.ts` checks it).

## Code Style

### Imports
- Third-party imports first, then workspace imports (`@smog/*`), then app-local imports (`@/`)
- Use `@/` alias for app-specific imports
- Use `@smog/package-name` for workspace imports

Example:
```ts
import { Ionicons } from "@expo/vector-icons";
import { BORDER_RADIUS, SHADOWS } from "@smog/styles";
import { useTheme } from "@/context/ThemeContext";
```

### Naming Conventions
- Components: PascalCase (`GestureCard`, `BottomSheet`)
- Hooks: camelCase with `use` prefix (`useBottomSheet`, `useAutoSync`)
- Services/Instances: camelCase (`gestureService`, `databaseService`)
- Types/Interfaces: PascalCase (`GestureCardProps`, `GestureCardRef`)
- Constants: UPPER_SNAKE_CASE (`BORDER_RADIUS`, `SPACING`)

### TypeScript
- TypeScript 7 (native `tsc`), strict mode, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`
- Extend a base from `@smog/config/tsconfig/*.json` (`library`, `react`, `worker`, `react-native`)
- Use `type` keyword for type-only imports: `import type { Gesture } from "@/types"`
- Explicit types for function parameters and return values

### Runtimes
- Code that runs in the Worker (`apps/site`, feature `./server`, jobs, db) never uses `Bun.*`
- Bun is for scripts, tests and the toolchain
- Env and bindings are validated once per runtime with the schemas in `@smog/config/env/*`

### Error Handling
- Use try/catch in async functions
- Log errors with service name prefix: `[serviceName] Failed to ...`
- Rethrow errors for calling code to handle

Example:
```ts
try {
  await service.doSomething();
} catch (error) {
  console.error("[serviceName] Failed to do something:", error);
  throw error;
}
```

## Project Structure
- `apps/site`: TanStack Start site and API on one Cloudflare Worker (routing, screens, wiring only)
- `apps/mobile`: Expo app (routing, screens, wiring only)
- `packages/*`: shared packages (`config`, `utils`, `db`, `auth`, `rpc`, `api`, `local-store`, `payments`, `video`, `email`, `jobs`, `analytics`, `i18n`, `styles`, `brand`, `ui-web`, `ui-native`, `migrate-convex`, `pdf`)
- `packages/migrate-convex`: the Convex → D1 importer (Bun CLI in `src/cli`, pure `src/core` with no `Bun.*`, `node:*` or `cloudflare:*`; nothing depends on it; `docs/cutover-runbook.md`)
- `packages/features/*`: feature packages (`gestures`, `favorites`, `lists`, `account`, `sponsorships`, `admin`, `translation`, `lessons`) with `./schema`, `./contract`, `./server`, `./client` subpath exports
- `scripts/*`: Bun scripts (boundaries check, release and deploy config checks, resource provisioning, admin grant, maintenance, retention, EAS update wrapper)

Package names are `@smog/<dir>` (`@smog/gestures`, not `@smog/features-gestures`).

## Dependencies
- Allowed dependency directions live in `@smog/config/boundaries` and are enforced by `bun run boundaries`; add a package there before depending on it
- Shared versions go in the root `package.json` `workspaces.catalog` and are referenced as `"catalog:"`
- Use the newest stable version of every dependency; a deviation needs a `docs/DECISIONS.md` entry. The 2026-10-28 sweep upgrades Bun to 1.4.4, Biome to 2.6.3, Vitest to 5, Expo to SDK 58 and Jest to 30. Compatibility exceptions are SDK 58's native/renderer pins (React 19.3.0, React Native 0.88.0 and the native-module versions selected by Expo), NativeWind 4's Tailwind 3/CSS Interop line, and Babel 7 for Expo's parameter transform. The native TS config temporarily uses React Native's documented `react-native-legacy-deep-imports` condition; migrate refs to instance types before RN removes it after 0.89. All exceptions and the preserved lint policy are recorded in `docs/DECISIONS.md`.
