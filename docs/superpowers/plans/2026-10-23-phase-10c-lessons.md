# Phase 10c: Teacher lessons and PDFs implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A teacher or admin enters private teaching information and drawings per gesture and language, builds lessons (sections, ordered gestures, per-language title and notes) and downloads a PDF for teachers or for participants in a chosen language; mobile lets a teacher list, view and share the PDFs.

**Spec:** `docs/superpowers/specs/2026-10-23-phase-10c-lessons.md` (approved by the owner, 2026-10-24: "Write implementation and continue"). Roadmap: `docs/superpowers/plans/2026-10-21-phase-10-roadmap.md`. It builds on phase 10a (shadcn kit, admin shell) and phase 10b (languages as data, per-language gesture rows, `teacher` role, presigned R2 flow, audit guard).

Phases 0 to 10b are done and deployed to staging (`develop` HEAD at plan time `eb6505c`). The next free migration number is **0024**.

**Nothing in this phase deploys by hand, and the session has no Cloudflare, Mux, Mollie, EAS or store credentials.** Every push to `develop` deploys staging after CI, so each merge leaves CI green. Staging's built `wrangler.json` (hash `f4d0e5823a0924d8dca046dd87ac11bef296919314fc59800bbe327b4308070f`, keys `configPath` and `userConfigPath` dropped, sha256 of `json.dumps(sort_keys=True)`) must not change: this phase adds no binding, queue, cron, var or Durable Object. New routes are normal Worker routes; the PDF cache lives in the existing R2 bucket.

## Rulings made for this plan
These go into `docs/DECISIONS.md` with the task that implements them.
1. **Package layout.** `packages/features/lessons` (`@smog/lessons`, with `./schema`, `./contract`, `./server`, `./client` like its siblings) owns teacher info, drawings and lessons. The PDF layout engine is a separate pure package `packages/pdf` (`@smog/pdf`): input is a plain validated document description, output `Uint8Array`; no D1, R2, `Bun.*`, `node:*` or `cloudflare:*` (so it runs in tests, the Worker and, if R1 forces it, a browser). Both are added to `@smog/config/boundaries` first (`@smog/lessons` may depend on `@smog/pdf`, `@smog/gestures` read helpers, `@smog/rpc`, `@smog/db`, `@smog/i18n`; nothing depends on `@smog/pdf` except `@smog/lessons` and the site).
2. **Teacher data never shares a table, query or output schema with public data.** `gesture_teacher_info` and `gesture_drawing` are only read by `@smog/lessons/server`; a guard test walks every public contract output schema and every public gesture query's column list and fails on a teacher column or drawing key (extend it when a new public output appears).
3. **One version counter decides PDF freshness.** `lesson.version` is bumped on every lesson write; `gesture_teacher_info.version` and the drawing `updated_at` are bumped on their writes. A cached PDF key is `teacher/pdf/<lessonId>/<fingerprint>-<template>-<locale>.pdf` where the fingerprint is a short hash of `lesson.version` plus, for each contained gesture, its teacher-info versions for the locale and the default language, its drawing ids, and the gesture name/translation `updated_at`. A stale file is therefore never matched, no invalidation fan-out is needed, and the daily retention sweep deletes `teacher/pdf/` objects older than 30 days.
4. **The PDF engine is `pdf-lib` + `@pdf-lib/fontkit`**, loaded only by a dynamically imported chunk of the export route (never reachable from a client entry and checked by the deploy guard). Figtree regular and bold TTFs (the OFL files already in the repo for mobile, `apps/mobile/assets/fonts`) and the brand logo PNG are bundled as Worker assets via the build's binary import; the Worker size and the cold-start cost are measured in Task 1 and recorded (spec R1, R2). If a spike shows `pdf-lib` cannot run in the Workers pool, the task stops and asks.
5. **Roles.** Write: teacher or admin writes any language; a translator writes only non-default languages of teacher info (text only; never drawings); anyone else nothing. Read of teacher info, drawings, lessons and PDFs: teacher, translator (teacher info and drawings only for the editor, not lessons) and admin. Lessons and PDFs: teacher and admin only. Every procedure has its own guard and authz row.
6. **Drawings use the audio upload design** (presign plus signed same-origin fallback, finalize with magic bytes PNG/JPEG/WebP, 1 MiB, 2000 px read from the header, fresh server key, orphan cleanup on replace) and a private route; they are never served from a public URL or CDN cache.
7. **Lesson edits are optimistic with a stale-lock** (`CONFLICT` with the other version) exactly like the 10b translation saves, autosaved by the client.
8. **Audit.** New kinds (closed CHECK list rebuilt like migration 0023): `teacher.info_save`, `teacher.drawing_upload`, `teacher.drawing_delete`, `lesson.create`, `lesson.update`, `lesson.delete`, `lesson.duplicate`, `lesson.export`; entries carry ids and counts, never texts, never PDF bytes.

## Global constraints (every task)
- Read `AGENTS.md`, the spec, and `docs/DECISIONS.md` (the phase 10b sections on roles, audio, translation audit, FTS, the admin guard).
- TDD. Migrations are append-only from 0024: one migration per concern, generated with `bun -F @smog/db db:generate`, snapshots checked, and a rebuild of a table other tables reference backs up and restores them (see `docs/DATA_MODEL.md`); tests on a fresh D1 and on a D1 migrated from 0023 with seeded data.
- No `Bun.*` in Worker code; no new Worker binding or config change; budgets in `apps/site/perf-budget.json` hold, a new route needs an entry, heavy code is a lazy chunk; the Worker cap is checked.
- Every new oRPC procedure gets a row in `packages/api/test/authz.test.ts` and a banned and cross-role case in `apps/site/test/security-authz-*.test.ts`; every mutation writes an audit entry in the same D1 batch; every new route gets a row in `scripts/security-guard.test.ts` (limiter or "none" with a reason).
- New strings in nl, en and fr (parity and typography tests), no hard-coded copy; kit and a11y contracts hold (44 px, focus ring, reduced motion, AA contrast, axe on every new screen, 320 px reflow); shadcn vocabulary only; the shadcn kit before any new component.
- Checks per task: `check:ci`, `check-types`, `bun run test`, `build` (budgets), `knip`, `boundaries`, the staging `deploy:dry` hash unchanged, affected e2e projects one at a time with CI-matching settings (AGENTS.md); no `waitForTimeout`; a pass-on-retry is a bug.
- The container restarts every 30-45 minutes: state file, draft report first, small commits.
- Each task appends its own `## ... (phase 10c task N)` section as the last block of `docs/DECISIONS.md` and writes `task-N-report.md`.
- Fixtures use invented names and `@example.test`; no teacher text in a log or an audit row.

## Review focus (every task reviewer)
Privacy leaks (a teacher field, drawing key or PDF reachable without the role: public outputs, search, sitemap, caches, logs, errors), authorization per procedure and route (translator limits, demoted users, banned users), upload validation, data loss in migrations, stale-lock and autosave races, PDF correctness (fallback marks, ordering, empty cells, long text overflow, rows split across pages, unpublished gestures), CPU and size caps actually enforced, cache key completeness (a stale PDF served), bundle growth, tests deleted rather than updated.
