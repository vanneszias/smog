# Phase 10b: Translate everything implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything a learner reads, hears or sees can be translated by non-developers in an admin UI: interface strings, emails, legal texts, gesture and category content, and one spoken audio clip per gesture per language; a gesture is one textless video with its name overlaid in the viewer's language; languages are data; roles become a set (translator, teacher, admin).

**Spec:** `docs/superpowers/specs/2026-10-22-phase-10b-i18n.md` (approved by the owner, 2026-10-22). Roadmap: `docs/superpowers/plans/2026-10-21-phase-10-roadmap.md`. Spec 3 (lessons) is a separate plan that reuses the per-language gesture data and the `teacher` role built here.

Phases 0 to 10a are done and deployed to staging (`develop` HEAD at plan time `e065469`). The next free migration number is **0015**.

**Nothing in this phase deploys by hand, and the session has no Cloudflare, Mux, Mollie, EAS or store credentials.** Every push to `develop` deploys staging after CI, so each merge leaves CI green. Staging's built `wrangler.json` (hash `5c706b1c16adc89e253bdeaa5d73c1c36b1bbf1438aece8f0ba9799e66fc30bb`) must not change: this phase adds no binding, queue or cron; the audio route is a normal Worker route.

## Owner decisions this plan implements
One sign per gesture (one textless video; translations are name, keywords, audio, details); no language in the URL; interface strings editable in a table plus import/export; everything editable including emails and legal texts; **any translator can publish a legal text** (risk R1); roles as a set; fallback to nl with a flag; learner search is active-language only with the nl row as the fallback for untranslated gestures; audio is MP3/M4A in R2 by presigned PUT served through a cached Worker route; the sponsor message becomes an **app-side overlay**; **the render pipeline is retired only after the owner confirms (Task 9 is gated)**.

## Rulings made for this plan
These go into `docs/DECISIONS.md` with the task that implements them.
1. **Overlay, not replacement.** Shipped JSON catalogues stay the base layer and the offline fallback; `ui_string` rows overlay them. A missing key resolves: D1 value for the locale, shipped value for the locale, D1/shipped value for `nl`. The overlay is read through a KV-versioned cache (`i18n:version`, bumped on every translation write, like `catalog:version`) and merged once per isolate; the shipped files are never edited by the UI.
2. **The default language is data, not a type.** `Locale` becomes `string` validated against the `language` table at the edges (RPC context, cookie, import); the compile-time key types keep deriving from the shipped nl catalogue; `INTL_LOCALE` comes from `language.intl_tag`. The CHECKs on `user.locale` and `sponsor.locale` become foreign keys to `language(code)` (table-rebuild migration, data copied, idempotent).
3. **Default-language columns stay.** `gesture.name`, `description` and `category.name` stay the nl value; other languages live in `*_translation` tables. No existing reader breaks; localized reads go through one function (`localizeGesture(row, locale)`) that applies the fallback and reports `fallbackUsed`.
4. **Search rows per locale.** `gesture_fts` is rebuilt with a `locale` column (hand-written migration; drizzle does not model virtual tables); one row per (gesture, locale); a query searches the active locale's rows plus the nl row of every gesture that has no row in that locale. Rebuilds run in the same batch as the translation write.
5. **Roles as a set.** `user_role` (translator, teacher, admin) is the source of truth; `user.role` stays mirrored (`admin` or `user`) so Better Auth and every existing check keep working; `requireRole(...roles)` is the new guard, `admin` implies all; sessions carry `roles: string[]`. The last-admin trigger is recreated on `user_role`.
6. **Audio is verified server-side.** Magic bytes (MP3 frame sync or ID3, M4A `ftyp`), 1 MiB, 10 s (from the container metadata), key `audio/<gestureId>/<locale>/<uuid>`; served from `GET /api/audio/<key>` with `Cache-Control: public, max-age=31536000, immutable` (the key changes on replace) and `Range`; the CSP gains no external source.
7. **Legal texts are versioned rows.** Draft then publish; publish needs the `translator` or `admin` role (owner decision), restore needs `admin`; Dutch stays canonical and the other languages keep the translation notice; the shipped TS texts seed version 1 and remain the fallback.
8. **The needs-recut flag** is `gesture.needs_recut` (default 1 for existing rows via the migration, 0 for gestures created after it with a textless video): the overlay name is hidden while it is 1 because the picture already carries the name.
9. **The sponsor end card replaces re-rendering.** New sponsorships stop creating render jobs once Task 8 lands (a gate in the paid-sponsorship step, not a deletion); the render code stays until the owner confirms Task 9.

- **`expo-audio` is a new native module:** the next EAS build must be native (already required by Figtree).
