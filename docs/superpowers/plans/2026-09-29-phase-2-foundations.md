# Phase 2: Foundations implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The shared foundations every feature builds on:
- the D1 schema and migrations
- Better Auth with all sign-in methods on web and mobile
- the oRPC base and composition packages with typed clients on both apps
- the on-device guest store
- design tokens, brand assets and translations
- the two UI kits with a component preview
- app shells with navigation, theme, language and auth screens.

**Architecture:** see spec §4–§7, §11 and §16. The packages are `utils`, `db`, `email` (core only), `auth`, `rpc`, `api`, `local-store`, `styles`, `brand`, `i18n`, `ui-web` and `ui-native`, and the site and mobile shells consume them. There is no feature logic yet (phase 3).

**Tech stack:** Drizzle ORM + drizzle-kit (D1/SQLite), Better Auth (+ passkey, expo, admin, emailOTP, magicLink, captcha plugins), oRPC (`@orpc/contract`, `@orpc/server`, `@orpc/client`, `@orpc/openapi`, `@orpc/tanstack-query`), TanStack Query, Zod 4, Tailwind v4, Radix primitives + cva + tailwind-merge (web), NativeWind 4.2 (native), i18next + react-i18next, sharp (brand generator only), Vitest 4 + `@cloudflare/vitest-plugin`, `bun test`, Jest + jest-expo.

**Spec:** `docs/superpowers/specs/2026-09-29-cloudflare-rewrite-design.md`

## Global constraints

- Everything in `docs/superpowers/plans/2026-09-29-phase-1-monorepo-skeleton.md` "Global constraints" still applies: newest stable versions, the catalog, current docs, no `Bun.*` in workerd, code style, commit trailer, and never running `playwright install`.
- React is pinned to 19.2.3 repo-wide (DECISIONS). The site builds with `CLOUDFLARE_ENV` (`dev` by default). Deploys go only through `bun -F @smog/site deploy`.
- Every new package:
  - is named `@smog/<dir>`, `private: true`, `type: module`
  - lists exports per subpath (§4.2)
  - has its tsconfig extend a `@smog/config/tsconfig/*.json` base
  - defines `check-types` and `test` scripts
  - is added to knip workspaces
  - satisfies `bun run boundaries`.
- Features are not built in this phase. Anything feature-specific (gesture tables' services, favorites …) waits for phase 3. The only exception is the db schema, which holds **all** tables of spec §5 now, so migrations start complete.
- Timestamps are integer ms; ids are text from `crypto.randomUUID()` (use `@smog/utils` `newId()`).
- The data model must follow spec §5 exactly: column names snake_case in SQL, camelCase in TS. The FK `ON DELETE` rules are exactly as listed there.
- All user-facing strings come from `@smog/i18n`. There are no hard-coded copy strings in kits or apps (a11y labels included).
- Colour, spacing, radius, type, elevation and motion values come only from `@smog/styles`. Apps and kits never write hex values or arbitrary Tailwind values (`[#…]`, `[13px]`).
- Local dev must keep working with no Cloudflare account: `bun dev` runs the site with local D1, KV and rate-limit bindings. OAuth providers are optional in dev; if the client id is missing, that provider button is hidden.

## Review focus

1. A migration generated by drizzle-kit must apply cleanly with `wrangler d1 migrations apply DB --env dev --local` on a fresh `.wrangler` state. The hand-written FTS5 migration must be ordered after the tables.
2. Better Auth on workerd: password hashing must stay within Workers CPU limits (use Better Auth's documented Workers-friendly hasher if the default scrypt is too slow; measure in the test). Cookies must work on `http://localhost` in dev (no `Secure` in dev) and be `Secure` in staging/production.
3. The Expo client must store the session in SecureStore and send the cookie header on oRPC requests. Deep link `smog://` must be a trusted origin.
4. Theme on web must not flash on SSR: the theme cookie is read on the server and the `dark` class is set in the server-rendered `<html>`. System theme follows `prefers-color-scheme` without a flash (inline script before paint).
5. Kit components need accessible names and focus rings, tap targets ≥ 44 px, and must respect `prefers-reduced-motion`. Tests assert the roles and labels.
