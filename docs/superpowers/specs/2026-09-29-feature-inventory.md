# SMOG feature inventory (old system to full rewrite)

Date: 2026-09-29 · Source of truth for **what** the rewrite must do. The design spec (`2026-09-29-cloudflare-rewrite-design.md`) says **how**. Where they disagree, this inventory's business rules win unless the spec or `docs/DECISIONS.md` explicitly changes them.

Sections: 1 Scope and legend · 2 Feature tables (Learning, User, Sponsorship, Admin, Platform) · 3 Background jobs · 4 Emails · 5 Webhooks and internal endpoints · 6 External integrations · 7 URL patterns and deep links · 8 Old bugs the rewrite must fix.

## 1. Scope note and legend

**Scope.** Everything the old platform did, from the analysis of `origin/master` (`docs/superpowers/analysis/01-convex.md` … `05-docs-shared.md`): Convex backend, Hono + oRPC server, Vite web app, Expo native app, Remotion service, docs and shared packages. Each row maps an old item to its new home in the rewrite (spec §4 layout, §5 data model, §7 endpoints, §8 jobs, §9 routes, §10 mobile, §11 guests, §12 analytics). "Done" boxes are ticked by later phases when the row is implemented and tested.

**Status legend.**

| Status | Meaning |
|---|---|
| `parity` | Same behaviour and same constants. |
| `improved` | Same business rules, better implementation or UX (no rule change). Spec section named. |
| `changed` | A rule, constant, name or state changed on purpose. Cites a `D-xx` DECISIONS entry (table below). If no entry exists yet, the row says `no DECISIONS entry` and is listed in 1.3. |
| `dropped` | Not carried over. The reason is given. |

**Id prefixes.** `L-xx` Learning · `U-xx` User · `S-xx` Sponsorship · `A-xx` Admin · `P-xx` Platform. Ids are stable: never renumber, only append.

### 1.3 Rule changes that have no DECISIONS entry yet

These rows carry `no DECISIONS entry` in the tables. They are visible in the spec but not recorded in `docs/DECISIONS.md`; add an entry (or confirm as improvement) before the phase that implements them.

1. Guests have no database rows; guest data lives on the device (spec §1, §11). Consequence: guest cron cleanup, guest consent rows, guest `migrateGuestToUser` are gone. `D-LOCALSTORE` covers the package only.
2. Category filter uses category slugs in `?category=` instead of category names (spec §9).
3. Auth provider switch WorkOS to Better Auth with new methods (email + password, OTP, magic link, Google, Apple, passkey) (spec §6). `D-AUTH` lists plugins; the provider switch itself is not a separate entry.
4. Admin sponsorship data model: sponsor/invoice/payment split; CSV columns change (spec §5.4).
5. Rate limits are implemented with Workers Rate Limiting bindings (numbers unchanged, spec §7).
6. Mux webhooks are new (old system polled) (spec §8.2).
7. Search typo tolerance: the old Fuse.js fuzzy tier (threshold 0.4) has no explicit successor in the spec (FTS5 with diacritic folding and prefix only).
8. Sign-in page/route names `/sign-in` etc. replace `/login` and `/callback` (spec §9; legacy redirects listed in section 7).
9. Web guests can now keep favorites and lists locally (old web had no guest mode) (spec §11).
10. Mobile `Favorites` tab is new (old app had Home, Search, Lists) (spec §10).
11. Legal pages become localized (old: Dutch only) (spec §9).
12. Turnstile on public mutations and auth endpoints (spec §6, §7).

## 8. Old bugs the rewrite must fix

Numbering is stable (referenced from the tables above). Format: bug, then **Fix**.

1. `sponsorship_live` e-mail used the `endDate` read before approval (stale). **Fix:** compute `starts_at`/`ends_at` in the approve transition and email the stored values (E-04).
2. Renewal e-mail footer said "over ongeveer 7 dagen" while the cron window is 30 days, and the button linked to the homepage. **Fix:** copy says 30 days; button goes to `/sponsor/renew?token=` (E-05, D-RENEW).
3. `generatePreview.sponsorName` was validated but unused; `overlayText` max 100 could 400 at Remotion (max 35). **Fix:** one `display_name` <= 35 shared by schema, Player and renderer (D-NAME).
4. Three overlay layouts existed (router 22/76/3.8/87, `DEFAULT_OVERLAY_CONFIG` same, older preset 15x15 y78 / text 4 % y85 used by the legacy render-at-payment path). **Fix:** one fixed layout constant in `@smog/render` (P-31, D-OVERLAY).
5. Admin "new sponsorship" mail was sent at creation, even for checkouts never paid. **Fix:** send after payment (E-06, D-ADMINMAIL).
6. Amount check ran only in the bulk webhook branch; e-mail dedupe relied on BullMQ job retention. **Fix:** verify amounts for every payment; idempotency by payment status plus KV idempotency keys (7 days) (W-01, J-06).
7. Remotion jobs lived in memory with unbounded parallelism, lost on restart, and API callers held HTTP requests up to 2 min. **Fix:** Workflow + durable `render_job` rows, Container concurrency managed by the platform (J-08).
8. node-cron used the container timezone and had no leader election (duplicates with >1 replica). **Fix:** Cron Triggers in UTC; handlers idempotent (section 3).
9. Stale cleanup measured `updatedAt` (reset by payment creation), did not cancel the Mollie payment, and a late paid webhook for a `cancelled` sponsorship threw, so Mollie retried forever with money taken. **Fix:** measure from payment creation, cancel the Mollie payment, revive or `refund_needed`, always 200 (J-03, W-01, D-STALE, D-LATEPAID).
10. Service and API keys were compared with non-constant-time string equality (`INTERNAL_API_KEY`, `REMOTION_API_KEY`). **Fix:** no shared-secret internal HTTP endpoints remain (W-05, W-06); any remaining secret compare uses a constant-time helper.
11. `admin.users.updateRole` was not audit-logged; CSV export was capped at 10,000 rows with no date UI. **Fix:** audit every role change (`user.role`); remove the cap or page it, add a date range, audit the export (A-09, A-12, A-23).
12. GDPR export omitted sponsorship data and listed stale processors; account deletion did not delete the identity-provider account. **Fix:** export includes sponsor/sponsorship/payment data and current processors; deletion removes the Better Auth user (U-24, U-25).
13. `cleanupInactiveGuests` also deleted migrated users that still carried a `guestId`. **Fix:** guests have no rows, job removed (J-05).
14. `migrateGuestToUser` did not check for an existing user with the same `workosId`, and any holder of a guest id could take over that row (guest `_id` acted as a bearer secret). **Fix:** no server guest rows; guest data imported through an authenticated, merging `account.importGuestData` (U-27).
15. `favorites.*` and `getUserByGuestId` had no auth (any caller could read or change favorites by userId); shared-list edit mutations trusted an unvalidated `userId`. **Fix:** every user-scoped procedure runs behind `requireUser` and derives the user from the session; shared edits need the edit-role token and a session (U-14, U-21).
16. `users.listAllUsers` ignored its cursor, so pagination was broken (and returned the last `_id` as cursor). **Fix:** real pagination via the admin plugin list API (A-23).
17. The conflict check ignored `pending` and `pending_resubmission` although `BLOCKING_STATUSES` listed more; gestures in `pending_resubmission` showed as available. **Fix:** database partial unique index over all blocking statuses; availability endpoint uses the same list (S-02, S-04).
18. Statuses, admin actions and target types were free strings. **Fix:** CHECK-constrained enums from shared const arrays, Zod discriminated unions for JSON (D-STATUS, D-AUDIT).
19. `reject` and `expire` had no status guards (rejecting an active sponsorship never restored the video); `approve` could overwrite another active sponsorship's video. **Fix:** `transition()` allows each event only from its listed states; the video is joined, never copied; unique blocking index (S-15, S-18).
20. Convex cron comment claimed "January / yearly" while the code ran monthly. **Fix:** one documented schedule (J-04).
21. Disclaimer/course banner: native showed it once per playthrough at <= 5 s left, web/docs after `VIDEO_COMPLETE_COUNT = 7` videos; `HOOKS.md` also claimed AND-logic for category filters (it is OR). **Fix:** a single `CourseBanner` rule shared by both apps (count completed videos to 7, shown near the end via `onNearEnd`), documented; docs corrected (L-13, L-03).
22. Stale copy: wizard error text said 40 characters while 35 was enforced, `wizard.maxCharacters` said 10, logo help said 400x400 while guidelines said 800x800. **Fix:** one constant per limit rendered into all copy (S-05, S-06).
23. The wizard checked logo type only through `accept`; the logo was accepted but not persisted (base64 in a legacy field). **Fix:** server validates MIME and size (2 MB) and stores the logo in R2 (S-06).
24. Success page total used `toFixed(2)` with a `€` prefix instead of `formatPrice`; the generic `/success` page was unreachable; the "5 sec" value card was hard-coded. **Fix:** `formatMoney`, redirect `/success`, derive "5 sec" from the overlay constant (S-14, R-14).
25. `MAX_GESTURES_PER_SPONSORSHIP = 10` was exported but unused, the API allowed 20 and the web enforced nothing. **Fix:** 10 enforced in schema, server and UI (S-03, D-MAX10).
26. `openInApp` built `smog:///gestures/<id>` (three slashes) and fell back to https after 500 ms regardless of success. **Fix:** `smog://gestures/<slug>`; keep the 500 ms fallback (L-15).
27. Admin gaps: status filter lacked `cancelled`, category delete was offered only for active cards, no logs/users UI, admin text hard-coded English. **Fix:** full status filter, complete tables, i18n (A-08, A-22, A-23, A-24).
28. Dutch e-mails could contain the English fallback "your gesture". **Fix:** localized fallback phrase (spec §8.3).
29. Every wizard preview created an orphan Mux asset for abandoned checkouts. **Fix:** browser-side Player preview; render once after payment (S-10, D-PREVIEW).
30. Admin e-mails silently skipped admins without a stored e-mail (`getOrCreateUser` never stored it); the welcome e-mail could be sent several times (first-login race, no jobId). **Fix:** e-mail is part of the Better Auth user; welcome uses an idempotency key (A-14, E-01).
31. Three divergent search implementations (Convex name-only FTS, native scoring 1000/750/500/300/200/100, web weighted Fuse ranking). **Fix:** one FTS5 index + one ranking function (L-07).
32. `markPaidManually` did not set the sponsored video, so a later approve failed with "Sponsored video playback ID is missing". **Fix:** manual payment enters `rendering`, so the same render path produces the video (A-10).
33. The maintenance page was served with status 200, without a rewrite to the index for other paths, and only by swapping containers. **Fix:** KV flag, 503 + `Retry-After`, admin bypass (P-11).
34. SEO: one static `<head>` for every route; sitemap had no gesture URLs; `HeadContent` rendered but unused. **Fix:** per-route head, SSR, dynamic sitemap (P-12, P-16).
35. `renewalReminderSentAt` was never reset, so a renewed sponsorship would never get a second reminder. **Fix:** reset `reminder_sent_at` on renewal payment (J-02).
36. The rate limiter failed open when Redis was down; webhooks and `/api/*` were unlimited. **Fix:** platform rate limiting bindings; webhooks stay unlimited but verified (P-09).
37. Shared list links could not be opened in the native app (token treated as own list id). **Fix:** `shared/[token]` route and AASA `/lists/*` (U-21, R-22).
38. `recordGuestConsent` needed no auth, created guest rows without the default list and without the guest-id length check. **Fix:** guest consent stays on the device; server consent is authenticated and append-only (U-23).
39. Gestures could be created twice with the same name, and `createBulkSimplified` did not check `isActive` on the gesture. **Fix:** unique slug + duplicate-name warning; checkout requires a published gesture (A-17, S-12).

Legacy code paths stayed in the system (`create`, `createBulk`, `updateAfterPayment`, `durationWeeks`, `overlayImageStorageId`, `user_favorites`, `renderVideoAtPayment`, stale `/success`, dead Clerk-style `auth.*` keys, SQLite-era types). **Fix:** none of them are ported (migration maps them, see spec §15).
