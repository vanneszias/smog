# Phase 10b, spec 2: translate everything (draft for approval)

Status: **draft, awaiting the owner's approval.** Track 2 of `docs/superpowers/plans/2026-10-21-phase-10-roadmap.md`. It builds on the phase 10a design system (the translation screens use the shadcn admin kit) and prepares spec 3 (lessons), which reuses the per-language gesture data model defined here.

## 1. Goal
Everything a learner reads, hears or sees can be translated, by non-developers, in a simple admin UI: the interface, emails, legal texts, gesture names/keywords/details, categories, and the audio of every gesture. A gesture is one textless video; its name is shown on top of the video in the viewer's language and each language has its own spoken audio. Languages are data: nl, fr and en now, more added from the admin.

## 2. Owner decisions (2026-10-22)
| Topic | Decision |
|---|---|
| Sign variants | One sign per gesture everywhere: one textless video per gesture; translations are name, keywords, audio, details |
| Language in the URL | None. The cookie (web) and the local preference (mobile) stay; no prefixes; one slug per gesture |
| Interface strings | Editable table (key, source, one column per language, "missing" filter) **and** import/export (JSON/CSV); shipped catalogues remain the fallback |
| Editable scope | **Everything, including legal texts and emails** |
| Legal text publishing | **Any translator can publish** a legal text (see risk R1) |
| Roles | A user can hold several roles (user, translator, teacher, admin) |
| Fallback | Missing translation shows the default language (nl) and is flagged to translators/admins |
| Learner search | **Active language only** (see 5.4 for what that means for untranslated gestures) |
| Video | One textless video per gesture, the name is overlaid in the player (not burned in); existing burned-in videos stay as the fallback until replaced, with a "needs re-cut" list |
| Audio | A spoken pronunciation of the name, one clip per language per gesture; MP3 or M4A uploaded to R2 by presigned PUT, served through a cached Worker route |
| Sponsor overlay | **The sponsor message becomes an app-side overlay in the viewer's language, not burned into the video** (see 6, it retires the render pipeline) |
| Translator role | Limited to the translation screens |

## 3. What exists today (survey, 2026-10-22)
- **Interface:** one i18next namespace, `nl`/`en`/`fr` JSON (1764 leaves each, `fr` 1808 with `_many` plurals), nl canonical (types derive from it), parity enforced by `catalog.test.ts`. 88 plural keys. Includes the whole admin UI (833 keys) and 150 email keys. Locale: cookie `locale`, then Accept-Language, then `nl`; signed-in users also store `user.locale`; mobile uses a local-store preference or the device language. No locale in the URL.
- **Legal texts:** structured TS per locale (`packages/i18n/src/legal/*.ts`), Dutch canonical, effective date `2026-09-30`, owner sign-off in `docs/LEGAL-SIGNOFF.md`.
- **Gestures:** `gesture.name` (single language), `description`, `gesture_keyword` (synonyms), `category.name`; `sort_name` drives catalogue ordering; slugs derive from the nl name; **search is one FTS5 table (`gesture_fts`, nl text only)** followed by `rankGestures` (nl collation, typo tier); the catalogue cache is KV-versioned. No audio column. Videos: Mux `playback_id`; sponsor overlay text is burned into a re-rendered video by Remotion (`packages/render`).
- **Media:** R2 bucket per env with a presigned-PUT flow used only for sponsor logos (CORS allows PUT only from `SITE_URL`; no read path for audio; the CSP has no R2 `media-src`); mobile has `expo-video`, no audio library.
- **Roles:** `user.role` text with CHECK `user`/`admin`; hard-coded admin guard; every admin mutation must write an audit entry from a closed enum; a trigger keeps one admin.

## 4. Data model (new migrations, numbers from 0015)
1. **`language`**: `code` (BCP-47, PK), `name` (native name), `intl_tag` (e.g. `nl-BE`), `enabled`, `is_default` (exactly one: nl), `sort_order`. Seeded nl, en, fr. The CHECKs that hard-code the three locales on `user.locale` and `sponsor.locale` are replaced by a foreign key to `language` (a table-rebuild migration).
2. **`ui_string`** (interface strings): `key`, `locale`, `value`, `updated_by`, `updated_at`, `source_hash` (hash of the nl source when translated, to flag stale translations). The shipped JSON stays the base layer: at runtime a D1 overlay is merged over it (cached in KV with a version key like the catalogue cache); a missing key falls back to the shipped value, then nl. Plurals stay `_one`/`_other`/`_many` keys; placeholders (`{{count}}`) are validated on save (parity rule from `catalog.test.ts`).
3. **`gesture_translation`**: `gesture_id`, `locale`, `name`, `description`, `updated_by`, `updated_at`; **`gesture_keyword`** gains `locale` (the `C:` related meanings of spec 3 feed it). The existing columns on `gesture` remain the nl (default-language) value for now, so nothing that reads them breaks; `gesture_translation` rows exist for every non-default language. **`category_translation`** (`category_id`, `locale`, `name`).
4. **`gesture_audio`**: `gesture_id`, `locale`, `r2_key`, `content_type`, `size`, `duration_ms`, `updated_by`, `updated_at`; unique (gesture, locale).
5. **`legal_text`**: `kind` (`privacy`, `terms`), `locale`, `version`, `content` (the same structured block format, validated), `effective_date`, `published_by`, `published_at`, `status` (`draft`, `published`); the current published version per (kind, locale) is served; the shipped TS texts are the seed and the fallback. History is kept.
6. **Roles**: a `user_role` table (`user_id`, `role`, `granted_by`, `granted_at`) with roles `translator`, `teacher`, `admin`; `user.role` stays as the legacy single-value column for compatibility (`admin` there is mirrored), and a user with no rows is a plain learner. The `user_keep_one_admin` trigger is moved to the new table. `requireRole(...)` guards beside the admin guard; `admin` implies everything; Better Auth admin endpoints stay disabled. Audit actions get new kinds (table rebuild).
7. **Slugs** stay one per gesture, from the nl name (cookie-only language means one canonical URL).
8. **Gestures without a translation** are shown with the nl text and listed in a "needs translation" report per language (counts on the admin dashboard).

## 5. Behaviour
### 5.1 Interface and emails
- The merged catalogue (shipped + `ui_string`) is what `createI18n` loads, on the Worker and in the browser (the site gets the overlay in the root loader, mobile fetches it at start and caches it in the local store; a stale cache is fine, the shipped base always works offline).
- Emails render through the same merged catalogue, per recipient locale (`sponsor.locale`, `user.locale`).
- A new language works as soon as an admin enables it: untranslated keys show the nl text; `INTL_LOCALE` becomes the `language.intl_tag` column; the language menu lists enabled languages.

### 5.2 The translation screens (admin area, new "Translation" sidebar group; translators see only this group)
- **Strings:** a data table (key, namespace filter, source (nl), one editable column per enabled language, status chips: missing, stale (source changed), placeholder error), search, "missing in <language>" filters, bulk import/export (JSON and CSV, per language or all) with a dry-run diff before applying.
- **Gestures:** list with per-language status (name, description, keywords, audio); an editor with the nl source on the left and one tab per language; audio upload with a play button.
- **Categories:** the same, names only.
- **Legal:** per kind and language a block editor with preview; "Publish" creates a new version (audited); effective date is set at publish; Dutch stays the canonical text and other languages carry the "translation" notice, as today.
- **Languages (admin only):** add/enable a language (code, native name, Intl tag), set order; the dashboard shows the translation coverage per language.
- Every mutation writes an audit entry (new audit kinds).

### 5.3 Video, overlay and audio
- One **textless** Mux video per gesture. The player shows the gesture's name on top of the video in the viewer's language (a styled overlay inside the video frame, fades in, respects reduced motion, can be hidden by the viewer's preference; the same `Surface`-style component on mobile). Gestures whose video still has the name burned in keep it until replaced: a `gesture.needs_recut` flag (set for all existing gestures by the migration, cleared by an admin when they upload the textless video) hides the overlay for them (the name is already in the picture) and fills the admin "needs re-cut" list.
- **Audio:** a play button next to the name (hidden when no clip exists for the language; no fallback audio, a wrong-language clip is worse than none). Upload (admin/translator): `translation.uploadAudio` returns a presigned PUT (mirrors `sponsorships.uploadLogo`), key `audio/<gestureId>/<locale>/<uuid>`, max 1 MB and 10 s, MP3 or M4A verified by magic bytes after the upload (the declared type is never trusted), the previous object removed on replace. Playback goes through `GET /api/audio/<key>` (long immutable cache, `Range` supported) so the CSP needs only `media-src 'self'`, and the R2 CORS rule needs no change. Mobile: add `expo-audio`, no autoplay.
- Accessibility: the overlay name is the accessible name of the video (not repeated); the audio button has an i18n label; captions are not applicable (no speech in the video).

### 5.4 Search (active language only)
- `gesture_fts` becomes one row per (gesture, locale) with that language's name, keywords, category names and description (the `unicode61 remove_diacritics 2` tokenizer already handles fr accents). A query searches the active locale's rows only. **For a gesture without a translation in the active language the nl row is used as the fallback row**, so an untranslated gesture can still be found by its Dutch name (it is shown in nl with the flag) instead of vanishing; this is the one place the "active language only" rule bends, recorded in DECISIONS.
- `rankGestures` takes the locale (collation per language, `Intl.Collator(locale)`), `sort_name` stays the nl ordering for the catalogue keyset (the visible order of the catalogue in another language is by the nl sort name; per-language ordering is a follow-up if wanted), the catalogue cache holds a per-locale projection, rebuilds run in the same batch as every translation write (as today for gestures). A migration backfills the FTS rows.

### 5.5 Sponsor overlay in the viewer's language
- The burned-in sponsor intro and name are replaced by an **app-side overlay**: during the last seconds of the gesture video the player shows the translated message ("Possible thanks to …" from the catalogue) with the sponsor's name and logo, in the viewer's language, on web and mobile. The sponsored video is no longer re-rendered; the gesture's own textless video is played, and the overlay window is timed from the video duration.
- **As built (task 8):** `gestures.bySlug` returns `sponsor: { name, until, logoPath, endCard }` (`endCard` is false for an older sponsorship whose rendered video already carries the name); `VideoPlayer` (web and native) takes `endCard` and shows `SponsorEndCard` ("Made possible by", `endCard.message`, in the viewer's language; the name as typed; the logo from the public `GET /api/sponsor-logos/<uuid>`, served only for a running sponsorship) from `endCardStart(duration)` on: 4 s before the end, never before the middle of a short video, nothing until the duration is known. The wizard and re-edit previews show the same card over the gesture's poster. A paid sponsorship goes `awaiting_payment → in_review → live` (see the Cloudflare design's 5.5 amendment), with no render job.
- This **retires the render pipeline** for new sponsorships (the Remotion composition, the render Container, the Workflow, the Mux re-upload and the render lane). It is a large simplification (the render flip on the owner's list disappears) but it also changes what a sponsor receives (a branded end card inside the app, not a downloadable video). Decision R2 below needs the owner's explicit confirmation before the pipeline is deleted; this spec only adds the overlay and stops creating render jobs.

## 6. Mobile
Overlay name, audio button (`expo-audio`), the merged catalogue with a local cache, the language picker listing enabled languages. The translation and admin screens are web only.

## 7. Security and privacy
- The `translator` and `teacher` roles are least-privilege: translators reach only the translation procedures (one contract, one guard), never user data, sponsorships, payments or audit; the authorization table test (`packages/api/test/authz.test.ts`) gets a row per new procedure.
- Uploaded audio is verified by magic bytes, size- and duration-capped, served from a key the server controls; no user-supplied filename is used.
- Imports are validated (keys must exist, placeholders must match, size cap) and dry-run first; every apply is audited with a row count.
- A translated string is rendered as text (never HTML); legal text blocks use the existing restricted inline markup only.

## 8. Risks and open decisions
- **R1 (owner's choice recorded): any translator can publish a legal text.** The legal texts are the GDPR privacy notice and the terms; the sign-off in `docs/LEGAL-SIGNOFF.md` assumes a controlled text. Mitigations built in: every version is kept with who/when, the audit log records each publish, Dutch stays canonical with the translation notice, the previous version can be restored by an admin. The sign-off file gains an item that the owner accepts this process.
- **R2 (resolved 2026-10-23): retiring the render pipeline** (5.5). The owner confirmed; task 9 removed it (see the amendments, section 11).
- **R3: search while a gesture is untranslated** uses the nl row (5.4).
- **R4: stale translations.** A changed nl source marks translations "stale" instead of deleting them; they keep showing until a translator confirms or edits.
- **R5: bundle size.** The merged catalogue is fetched, not bundled: the shipped base stays in the bundle (about 70 kB gzip today); a per-locale split (already a post-launch carry) becomes worthwhile and is part of the plan. **Resolved in task 7b:** one catalogue chunk per language on the web (section 11).
- **R6: FTS cost.** Rows grow with (gestures x languages); at about 1000 gestures and 3 languages this is small for D1.
- **R7: roles migration** touches the sign-in/session path and the last-admin trigger; it ships with the authorization tests and a rollback note.

## 9. Implementation outline (the plan follows after approval)
1. Data foundations: `language`, `ui_string`, translations, audio, legal, roles tables and migrations; the guards and audit kinds.
2. Runtime catalogue: merged loader on Worker, web and mobile; overlay cache; `language` menu from data; emails.
3. Translation admin: strings table + import/export; categories and gestures editors; languages screen; dashboard coverage.
4. Gestures end to end: per-language reads (name, description, keywords), per-locale FTS and ranking, catalogue cache, sitemap unchanged.
5. Media: textless-video overlay in the player (web and mobile), `needs_recut` flow, audio upload/serve/playback.
6. Legal texts in D1 with versioning and publish; the sign-off item.
7. Sponsor overlay (and, once R2 is confirmed, removal of the render pipeline).
8. Close: docs, owner list, whole-phase review and fix wave.

## 10. Out of scope
Per-language video variants, language prefixes in URLs, machine translation, per-language ordering of the catalogue, automatic speech/audio generation, the lessons feature (spec 3).

## 11. Amendments: as built (phase 10b, task 10)

The spec above is the design; this is where the build differs from it or fixed a detail it left open. Each line has its reasoning under the task named in `docs/DECISIONS.md`.

- **Languages and the type (task 3).** `Locale` is a plain string; `ShippedLocale` is the union of the three bundled catalogues. The default language is the `language.is_default` row. Whether a code names an enabled language is checked where it is used, not in the type. Only the admin email preview's sample subjects and nothing else stay on the shipped three, apart from the maintenance page, which runs without KV or D1 on purpose.
- **The overlay cache (task 3).** The `i18n:version` read is memoised for 30 s per isolate on top of KV's own `cacheTtl`, so a text edit reaches other isolates in about one to two minutes (the writing isolate at once), not within a request. A root shell is loaded once per document, so an open tab shows an edit on its next load or language change. The mobile cache is the persisted TanStack query cache (`system.i18n`, one day), not the guest-data store.
- **Roles (tasks 1 and 2).** `user_role` is the source of truth and `user.role` is kept in step by two-way triggers (not dropped as 5.3 allowed), because several writers and the e2e seed still write `user.role`. `users.setRole` is replaced by `users.grantRole` and `users.revokeRole`. `account.export` still lists only the legacy role.
- **Migrations (task 1).** 0015 to 0023 as listed in section 4, with two corrections: D1 allows 100 bound variables, so `gesture_keyword.locale` and `gesture.needs_recut` have SQL defaults (a Drizzle default binds one more variable per row), and rebuilding `user` and `sponsor` cannot rely on `PRAGMA foreign_keys = OFF` in D1's migration transaction, so 0015 backs up every dependent row and restores it. The next free number is 0024.
- **Translation writes (tasks 4, 5 and 7).** The strings, languages and coverage are `translation.*`; gestures and categories are a second contract, `catalogTranslation.*` (the `admin.*` router is admin-only as a whole); legal texts are `translation.legal.*`. The audit guard moved to `@smog/rpc/audit` so both features share it. The strings table is paged on the server (100 rows), not virtualised. An import skips invalid rows and lists them in a dry run instead of refusing the file. Stale is a stored source hash: a shipped en or fr text is never stale and an import overwrites without the single save's conflict check. A gesture or category translation cannot be deleted; a blank name is refused.
- **Search (task 5).** The FTS rows of a language plus the default row of every untranslated gesture; ties sort with `Intl.Collator(locale)`; the browse order stays the default language's `sort_name`. The language of a read comes from the request context (cookie, then `Accept-Language`), so query keys carry no language and a language change resets the localized caches.
- **Audio and the overlay (task 6).** Splat routes `api/audio/$` and `api/audio/upload/$` instead of one key segment; the procedures are flat on `translation.*`; finalize verifies the bytes and copies to a fresh key; a new gesture upload takes `textless`. The player draws the name only for a textless video (`needs_recut = 0`). Never-finalized uploads stay in R2 (no sweep).
- **Legal texts (task 7).** A draft has a provisional number and is numbered at publish; there is no discard-draft procedure (no audit action in 0023). The new subpath `@smog/i18n/legal/markup` keeps the shipped texts out of client bundles. `CONSENT_POLICY_VERSION` stays a code constant.
- **The catalogue split (task 7b).** The web client loads only the active language's catalogue (the Vite plugin resolves `@smog/i18n` to `index.lazy.ts`); about 53 kB gzip off every route entry, at the cost of one extra request before hydration. The legal pages load the catalogue of the text's language and Dutch too.
- **The end card and the render pipeline (tasks 8 and 9).** Section 5.5 as amended: new sponsorships never enter a render state, and the pipeline was removed rather than gated. Old `rendering` and `render_failed` rows are moved to `in_review` by the hourly stale cron (trail event `render_succeeded` with `{ retired: true }`; no migration). Staging's built `wrangler.json` hash moved because the dead `RENDER_MODE` var was removed (`docs/DECISIONS.md`, task 9). The payment reconciliation that resent `payment.settled` for render rows is gone.
- **Not built, as the outline allowed.** Task 9 of the plan ran (R2 confirmed). Left open: deleting a translation or a language, an approval step for a translator's edits, per-language ordering of the table, a sweep of orphan audio objects, an admin way to discard a legal draft.
