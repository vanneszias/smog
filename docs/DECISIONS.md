# Decisions

Each entry: date · decision · alternatives · why. Newest entries go at the bottom of their section. Business-rule changes are marked **[rule change]**; UX changes **[ux]**; improvements **[improvement]**; dependency additions outside the approved list **[dep]**.

## Process

- **2026-09-29 · Superpowers followed by hand.** The plugin install was not possible in this environment (no `/plugin` command, the org catalog has no match). The skills were cloned from `github.com/obra/superpowers` into the session scratchpad and followed manually: brainstorming → spec → plans → subagent-driven TDD execution → verification → review. Alternative: skip the workflow. Why: the user asked for that workflow.
- **2026-09-29 · Review cadence.** Tasks are sized as cohesive slices (a package or a feature). Each task gets an implementer subagent plus a task reviewer subagent, and a whole-phase review runs between phases. Alternative: one reviewer per micro-step. Why: roughly 100 micro-tasks × 2 reviews would cost more than it catches; phase reviews keep the quality gate.
- **2026-09-29 · Brainstorming questions answered from the prompt.** Every open question was resolved from the user's brief; where the brief was silent the choice below was made.

## Toolchain and versions

- **2026-09-29 · Newest stable version of every package** (user request). A deviation is only allowed for a concrete incompatibility and is listed here.
- **2026-09-29 · TypeScript 7.x** (native `tsc`), per the user's request. TS 7 drops the classic JS compiler API. If a tool needs that API, that tool alone gets a scoped `typescript6` alias (`npm:typescript@6`); none is known yet.
- **2026-09-29 · Keep knip 6** for unused files, exports and dependencies (it uses oxc and does not depend on TypeScript, so it is compatible with TS 7). Dependency direction is enforced by a small Bun script, `scripts/check-boundaries.ts`, against the graph in `@smog/config`. Alternatives: drop knip (loses unused export/file/dependency detection), or dependency-cruiser (covers direction only and parses with the TS API when present). Why: no other tool covers workspace-wide unused code; the script needs no new dependency.
- **2026-09-29 · Vitest 4.x for the Workers pool.** `@cloudflare/vitest-pool-workers@0.22` requires `vitest ^4.1`; Vitest 5 is used nowhere else (pure packages use `bun test`). Revisit when the pool supports 5.
- **2026-09-29 · NativeWind 4.2.7 (stable) with Tailwind 3.4.19 on Expo SDK 57.** Verified in phase 1: `expo export` for iOS and Android compiles the classes (the bundle's injected stylesheet has `text-brand` → `#00805f`, `dark:` as a `prefers-color-scheme` media rule) and the JSX goes through `react-native-css-interop`'s runtime, with Reanimated 4.5.1 / Worklets 0.10.1 and the `babel-preset-expo` + `nativewind/babel` setup. Tailwind 3 lives in the mobile app only; Bun's hoisted linker nests Tailwind 4 under `@tailwindcss/*` for the site. Alternative: NativeWind 5.0.0-rc.0 + `react-native-css` 3.1.0-rc.0 + Tailwind 4 (targets exactly Expo 57, but still a release candidate). Revisit when 5.0 is stable (one Tailwind major across the repo). Not verified here: rendering on a device or simulator (none available in this environment).
- **2026-09-29 · Bun stays at 1.3.11 for now (deviation).** `bun upgrade` to 1.4.2 failed in this environment (the GitHub release download is blocked by the egress proxy, HTTP 403), so `packageManager` pins the installed `bun@1.3.11`. Alternative: pin 1.4.2 without being able to run it (CI would then test a version nobody ran locally). Revisit: bump `packageManager` to the newest 1.x once the toolchain can be upgraded.
- **2026-09-29 · TypeScript 7 `tsc -b` works with shared bases.** Library bases are `composite` and emit declarations only, into `${configDir}/node_modules/.cache/tsc` (TS 7 supports `${configDir}`), so nothing lands next to sources or in `dist/`. `worker.json` adds `${configDir}/worker-configuration.d.ts` (the `wrangler types` output) to `files` instead of depending on `@cloudflare/workers-types`. Alternatives: `--noEmit` per package (breaks project references) or a per-package `outDir` (repeated in every package).
- **2026-09-29 · Root Bun scripts are checked by root Turborepo tasks.** `//#test:scripts` (`bun test scripts`) and `//#check-types:scripts` (`tsc -p scripts`) run beside the package tasks in `bun run test` / `bun run check-types`. They are uncached because root tasks do not hash other workspaces' files (the scripts import `@smog/config`). Package `check-types`/`test` depend on a `transit` node, as the installed Turborepo docs recommend, so they run in parallel but still miss the cache when a dependency changes.
- **2026-09-29 · Workers tests use `@cloudflare/vitest-plugin` (the renamed pool).** `@cloudflare/vitest-pool-workers` stopped at 0.22.0 (2026-08-18) and pins wrangler 4.124; Cloudflare's current docs and releases use `@cloudflare/vitest-plugin` 1.x (same `cloudflareTest()` API, `import { exports } from "cloudflare:workers"` instead of the deprecated `SELF`), which pins the same wrangler as `@cloudflare/vite-plugin` 1.62 requires (4.143). It still needs Vitest ^4.1, so the Vitest 4.x exception stands. Alternative: the old package name (stale, a second wrangler/miniflare copy).
- **2026-09-29 · Site `worker-configuration.d.ts` is generated, not committed.** `check-types` runs `wrangler types && tsc -b` (offline; it only reads `wrangler.jsonc`), the file is gitignored, and `apps/site/turbo.json` lists it as the `check-types` output (its inputs are the default package files, which include `wrangler.jsonc`). It covers all envs, so each binding is optional on `Env` because the top level has none. `test` and `build` do not need it. Run `bun -F @smog/site cf-typegen` for editor types after a fresh clone. `src/routeTree.gen.ts` (small, stable, TanStack Router) stays committed. Why: the 600 KB file changes whenever a binding is added (every phase), which means noisy diffs and merge conflicts. Alternative: commit it and run `wrangler types --check` in CI.

- **2026-09-29 · React 19.2.3 across the repo (deviation from 19.3.0).** Expo SDK 57 pins `react` 19.2.3 (React Native 0.86.3 ships the 19.2.3 renderer, `jest-expo` pins `react-test-renderer` 19.2.3), and `react-dom` must equal `react` exactly. Two React versions in one hoisted monorepo would give shared packages (feature `./client` hooks, UI kits) a second copy of React in the mobile bundle. The catalog therefore pins `react`/`react-dom` 19.2.3 and `@types/react` 19.2.18 (`@types/react-dom` 19.2.7 in the site). Alternative: 19.3.0 for the site only, with Metro/Jest resolver pins in the app (two Reacts to keep apart forever). Revisit with the next Expo SDK.
- **2026-09-29 · React Native 0.86.3, not 0.87.** Expo SDK 57 (`expo` 57.0.26) bundles RN 0.86.3; RN 0.87.1 is on npm but belongs to the next SDK. The app uses the versions `expo install --check` selects.
- **2026-09-29 · Jest 29 for the mobile app (deviation from Jest 30).** `jest-expo` 57 depends on the Jest 29 packages (`babel-jest`, `@jest/globals`, `jest-environment-jsdom` ^29). Tests import from `@jest/globals` instead of `@types/jest` globals. Revisit when `jest-expo` moves to 30.
- **2026-09-29 · TypeScript 7 in the mobile app; `typescript` is excluded from Expo's dependency-version check.** `tsc --noEmit` passes with `expo/tsconfig.base` + `@smog/config/tsconfig/react-native.json` (composite/declaration turned off, since the app is not referenced by other projects), and `expo/types` is listed in `types` so CSS imports type-check on a fresh clone without the generated `expo-env.d.ts`. expo-doctor *does* check the TypeScript version online: SDK 57's api.expo.dev list pins `typescript ~6.0.3`, and the first CI run failed on it (the earlier claim that doctor has no TypeScript check came from an offline run, where that list is not fetched). `apps/mobile/package.json` sets `expo.install.exclude: ["typescript"]`, the mechanism doctor's advice names ("To ignore specific packages, add them to expo.install.exclude"; `@expo/cli` `validateDependenciesVersions` filters it). Metro, Babel (`babel-preset-expo` strips types) and Jest do not use the TypeScript JS API, so `expo export` and the Jest suite pass on TS 7. Alternative: a `typescript6` alias for the app only (two compilers, and the repo standard is TS 7).
- **2026-09-29 · No `EXPO_USE_PRECOMPILED_MODULES=0` in `eas.json`.** Precompiled Expo modules are on by default for iOS since SDK 56 and Android since SDK 53; source builds are only needed for patched native code or custom Reanimated/Worklets feature flags, and the app has neither. Alternative: keep the old app's opt-out (slower builds, no known reason).
- **2026-09-29 · Kebab-case file names in the mobile app** (`src/app-config.test.ts`, `plugins/with-screen-capture-permissions.js`), because the Ultracite `useFilenamingConvention` rule applies everywhere except Expo Router's route files. `global.css` gets a Biome override that allows the `@tailwind` at-rule (Tailwind 3 syntax), and the placeholder `apps/mobile/assets` are excluded from Biome.
- **2026-09-29 · `bun audit --production` ignores three moderate advisories (`bun run audit`).** Bun 1.3.11's `--production` does not drop dev dependencies from the report, and all three have no fix we can take: GHSA-3wwx-pv8p-q78v (undici 7.29.0 WebSocket deflate DoS) is pinned exactly by wrangler / miniflare / `@cloudflare/vitest-plugin` 4.143 (newest), is local dev tooling, and is not in the Worker bundle; an `undici` override would force srvx (8.x) and RN dev-middleware (6.x) onto one version. GHSA-w5hq-g745-h8pq (uuid 7.0.3 via `expo`/`expo-splash-screen`, only when a caller passes `buf`) and GHSA-vcc3-ghjq-m6fr (decode-uri-component 0.2.2 via `expo-router`) come from Expo SDK 57; the fixed versions are majors (uuid 11, decode-uri-component 0.5 is ESM-only) that the CJS consumers may not load. Alternatives: overrides (risk breaking Expo), or not gating on audit. Remove each `--ignore` when wrangler or the next Expo SDK moves.
- **2026-09-29 · `bun run audit` also ignores GHSA-67mh-4wv8-2f99 (esbuild ≤ 0.24.2, moderate).** It comes only from `drizzle-kit` 0.31.11 (newest stable) → `@esbuild-kit/esm-loader` → `@esbuild-kit/core-utils` (deprecated) → `esbuild` 0.18.20. The advisory is about `esbuild serve` answering cross-origin requests; drizzle-kit uses esbuild to load `drizzle.config.ts` and the schema and never starts a server, and it is a devDependency of `@smog/db` only (not in any bundle). Alternatives: a root `esbuild` override (would also move the exact esbuild versions wrangler and Vite pin), or drizzle-kit 1.0 rc (not stable). Remove the ignore when drizzle-kit drops `@esbuild-kit`.
- **2026-09-29 · `SMOG_OFFLINE=1` for expo-doctor's network checks (local only, not equivalent to CI).** expo-doctor 1.20 has no flag to skip a check; its documented env vars are `EXPO_DOCTOR_ENABLE_DIRECTORY_CHECK` (README) and `EXPO_DOCTOR_WARN_ON_NETWORK_ERRORS` (`build/utils/env.d.ts`, only for `fetch failed`/`ENOTFOUND`). Behind an egress proxy the schema fetch gets a 403 text body, which crashes the check with a JSON error that doctor does not count as a network error. Offline, `scripts/mobile-release-check.ts` sets both env vars, and three checks are degraded, which the script prints on every offline run: (1) the config schema check is tolerated only when doctor reports it as an "Unexpected error" (a crash, not schema issues) and the failure count matches; (2) "Check that packages match versions required by installed Expo SDK" (`expo install --check`) falls back to the bundled native-module list, so the api.expo.dev pins (react, react-native, typescript, jest-expo, …) are not checked and the check passes; (3) the React Native Directory check is off. Every other failure fails. CI does not set it (`release-config-check` asserts that), so CI is the authority. Alternative: an `expo.doctor` config in package.json, which only covers the directory check.
- **2026-09-29 · Deploy workflow: gated on the release check, migrations guarded by `packages/db/migrations`.** `deploy.yml` calls `ci.yml` as a reusable workflow (`workflow_call`) in a `release-check` job, and `deploy` `needs` it, so a red commit never migrates or deploys. Alternative: `workflow_run` on CI success (no duplicate run on develop/master pushes, but it needs `workflow_run.head_branch` for the env mapping and a checkout of `head_sha`); the cost of the chosen way is that a push to develop/master runs the release check twice (CI + Deploy). The migrations step `bunx wrangler d1 migrations apply DB --env <env> --remote` runs before `bun -F @smog/site deploy` and is guarded by `hashFiles('packages/db/migrations/*.sql') != ''`, the spec's location (phase 2 sets `migrations_dir: "../../packages/db/migrations"`). `release-config-check` derives the directory from `wrangler.jsonc` `env.<staging|production>.d1_databases[DB].migrations_dir` (default `packages/db/migrations` while there is no D1) and fails if the guard points elsewhere. The deploy itself is the guarded site script (`CLOUDFLARE_ENV` from the branch, asserted equal to `environment`), never a bare `wrangler deploy`.

- **2026-09-29 · [dep] `sharp` 0.35.5, a devDependency of `@smog/brand` only.** It rasterises the logo artwork into the committed PNG icons (`bun -F @smog/brand generate`); Bun has no image API and the ICO container is written by hand (`src/ico.ts`). Builds never run the generator. Alternatives: `@resvg/resvg-js` (SVG only, no PNG palette/flatten control), or committing hand-exported PNGs (drift nobody notices).

## Architecture

- **2026-09-29 · `@smog/rpc` split from `@smog/api`.** Features need the oRPC base (context, middleware, errors) and `api` composes the features; putting both in one package would create a cycle. `rpc` = base, `api` = composition + client. Alternative: features define their own base (duplicated) or live inside `api` (not modular).
- **2026-09-29 · `@smog/local-store` package** for the on-device guest store with web/native adapters (the brief asked for "one shared local-store abstraction"). Features' `./client` hooks use it when signed out.
- **2026-09-29 · Contract-first oRPC** (`@orpc/contract`), so the mobile bundle only ships contracts and schemas, never server code.
- **2026-09-29 · Jobs package owns message types, producers and schedules; handlers are wired in the site Worker.** This avoids a jobs ↔ features cycle.
- **2026-09-29 · No locale prefix in site URLs.** The language comes from a cookie, then `Accept-Language`, then `nl`. Why: old URLs (`/gestures/…`, `/lists/<token>`) and app links stay valid, and gesture content (the sign videos) is language-neutral. Alternative: `/{nl,en,fr}/…` as in the reference branch (better hreflang, but breaks every old link and deep link).
- **2026-09-29 · Gesture URLs use slugs** (`/gestures/<slug>`); old Convex ids resolve through `gesture.legacy_id` (301 on web, transparent lookup in the app).
- **2026-09-29 · Boundaries graph encodes subpaths.** In `@smog/config/boundaries`, a plain entry (`@smog/db`) allows the package and all subpaths, a subpath entry (`@smog/render/contract`) allows the dependency but only that subpath in imports, and `@smog/feature:*` (optionally `/schema`, `/client`) stands for every package in `FEATURE_PACKAGES`. Every package from spec §4.1 is listed now, before it exists, and a workspace missing from the graph is a violation. `scripts/check-boundaries.ts` checks declared `@smog/*` dependencies and every `@smog/*` import in a workspace's source files (forbidden subpaths and undeclared imports). `@smog/config` may be a devDependency of any package (for the tsconfig bases, spec §4.1 leaves it out of `ui-web`/`ui-native`); as a runtime dependency or import it is still checked. Alternative: Turborepo's experimental `boundaries` (tags only, no subpath rules).
- **2026-09-29 · The boundaries check also covers `optionalDependencies` and mock specifiers.** `vi.mock`/`vi.doMock`/`vi.importActual` and `jest.mock`/`jest.requireActual` (and friends) with an `@smog/*` string count as imports, so a test cannot mock a package its workspace may not use. Closes the phase 1 known gap.
- **2026-09-29 · Site Cloudflare env is chosen at build time with `CLOUDFLARE_ENV`, and deploys go through a guard.** With the Cloudflare Vite plugin, `vite build` flattens one wrangler env into `dist/server/wrangler.json` (`targetEnvironment`) and `wrangler deploy` uses that redirected config, so `--env` does not select bindings: a bare `wrangler deploy` ships whatever env `dist/` was last built for. `vite.config.ts` defaults `CLOUDFLARE_ENV` to `dev` (local dev, test builds, `vite preview`). Deploys only run through `bun -F @smog/site deploy` (`vite build && bun scripts/deploy-guard.ts && wrangler deploy --env $CLOUDFLARE_ENV`). The guard (`apps/site/scripts/deploy-guard.ts`, tested) requires `CLOUDFLARE_ENV` to be `staging` or `production` and the build's `targetEnvironment` to match, so a missing env, `dev`, or a stale build for another env fails before wrangler runs, and wrangler itself refuses an `--env` that differs from the build. `deploy:dry` = `CLOUDFLARE_ENV=staging bun run deploy --dry-run`. `apps/site/turbo.json` hashes `CLOUDFLARE_ENV` for `build` (and caches `.wrangler/deploy/**`, the redirect file), so a dev build is never replayed for staging. CI (`deploy.yml`) must call the `deploy` script, never `wrangler deploy` directly. Alternatives: build the top-level config by default (a deploy then ships without bindings), or `.env.<mode>` files (need `.gitignore` exceptions, same effect).
- **2026-09-29 · `parseWorkerVars` takes `object`.** The generated `Env` is an interface without an index signature, so `Record<string, unknown>` rejected `env` from `cloudflare:workers`; zod validates the shape anyway.
- **2026-09-29 · [dep] oRPC 1.15.4** (`@orpc/contract`, `server`, `client`, `openapi`, `zod`, `tanstack-query`, newest stable, in the root catalog). `@smog/rpc` has four subpaths: `.` (Worker: builders, middleware), `./contract` (`baseContract = oc.errors(ERRORS)`, `ERRORS`, `roleSchema`; only `@orpc/contract` + zod, so contracts in the app bundles never pull `@orpc/server`), `./react` and `./testing` (`makeRpcContext`, `makeSession` for feature tests). `roleSchema` is written out (`["user", "admin"]`) because `@smog/db` (`ROLES`) must not reach the app bundles; a type test keeps it equal to `@smog/auth`'s `Role` and the db enum.
- **2026-09-29 · rpc context shape.** `RpcContext.env` is `WorkerEnv` (new `workerEnvSchema` / `parseWorkerEnv` in `@smog/config/env/worker`: vars + secrets) plus the four rate-limit bindings, typed by a structural `RateLimiter` interface (the Workers `RateLimit` type is global only where `wrangler types` ran). The context has no `user`; `requireUser` / `requireAdmin` add it, so `context.user` is non-null exactly where a guard ran. The site builds the context once per request (`createRpcContext(request, siteEnv(), { waitUntil })`): the session with `getSession`, `ip` from `cf-connecting-ip` (`unknown` locally), `locale` from the `locale` cookie (TanStack Start `getCookie`), then Accept-Language.
- **2026-09-29 · rpc errors and middleware.** `ERRORS` carries statuses only (no messages; clients show `@smog/i18n` copy for the code): 409 for `CONFLICT`/`INVALID_STATE`/`GESTURE_UNAVAILABLE`/`PAYMENT_MISMATCH`, 410 `TOKEN_EXPIRED`, 400 `TOKEN_INVALID`, 403 `TURNSTILE_FAILED`/`FORBIDDEN`, 401, 404, 429, and `VALIDATION` 422 with `z.flattenError` data. `mapValidationErrors` (a handler `clientInterceptor`) turns oRPC's `BAD_REQUEST` + `ValidationError` into `VALIDATION`, so input errors are typed. Middleware throws `new ORPCError(code, { status })` instead of `errors.X()`, so it works on any contract; oRPC marks it `defined` when the procedure's contract declares the code (every `baseContract` procedure does). `logErrors` sits on `publicProcedure` and on every procedure of `implementRpc(contract)` (the contract-first implementer features use); ORPC errors below 500 pass silently, anything else is logged as `[rpc:<path>]` and replaced by a bare `INTERNAL_SERVER_ERROR`. Turnstile verification reads `x-turnstile-token` and posts `secret`/`response`/`remoteip` to siteverify.
- **2026-09-29 · Rate limits: the binding only has 10 s and 60 s periods.** The Workers Rate Limiting `ratelimits` config accepts `period: 10 | 60` only (docs and wrangler's schema), so the old 20/3600 s (sponsor) and 30/900 s (auth) windows cannot be expressed. `RL_SPONSOR` and `RL_AUTH` are 5/60 s: the old count spread over one minute rounds to 1 and 2, which would block a normal multi-step flow (send code + verify + a typo; logo upload + checkout), so the floor is 5 per minute. Long-run this is looser (auth 75/15 min instead of 30; sponsor 300/h instead of 20); Better Auth's own KV limiter still runs outside dev. `RL_API` 300/60 s and `RL_ANALYTICS` 120/60 s are exact. Namespace ids are unique per binding and env (dev 1001–1004, staging 2001–2004, production 3001–3004); miniflare enforces them locally, so dev and tests need no account. Where each applies: `RL_API` per IP on every request of both transports (`limitRequests("RL_API", "api")`, a handler interceptor, like the old `/rpc/*` limit); `RL_AUTH` per IP on `POST /api/auth/*` (429 `{ "code": "RATE_LIMITED" }`, `retry-after: 60`); `rateLimit(binding)` per procedure keyed `<ip>:<path>` for `RL_SPONSOR` (and `RL_ANALYTICS`) in later phases. Alternatives: a KV/D1 counter for the long windows (writes our own limiter, KV is not atomic), or 1–2/60 s (breaks flows). Revisit if abuse shows up.
- **2026-09-29 · Feature hooks get typed utils for their own contract slice.** `RpcProvider` holds the one app client and its `createTanstackQueryUtils` utils; `useRpcClient<{ gestures: GesturesContract }>()` / `useRpcQuery<…>()` cast to the slice's client/utils type. A feature therefore never imports `@smog/api` (boundaries). Safe because the app client has every slice under the same key; `@smog/api` fails to type-check if a feature router is not mounted under its contract key. Pattern in `packages/rpc/README.md`.
- **2026-09-29 · OpenAPI transport with oRPC's `OpenAPIReferencePlugin`.** `/api/openapi/*` is an `OpenAPIHandler` with the plugin (Zod 4 converter from `@orpc/zod/zod4`), which serves the generated document at `/api/openapi/spec.json` and the Scalar reference UI at `/api/openapi` (script from jsdelivr, dev/staging only). Enabled where `devToolsEnabled` is (not production, 404 there). Procedures have no `.route()` yet, so paths are the procedure paths (`POST /system/health`).
- **2026-09-29 · Mobile api client takes the cookie source instead of importing `@smog/auth/expo`.** `apps/mobile/src/lib/api.ts` exports `createMobileApiClient(authClient)`: `EXPO_PUBLIC_API_URL`, the `cookie` header from `await authClient.getCookie()` (async in `@better-auth/expo` 1.7.6) and `credentials: "omit"`. Importing `@smog/auth/expo` from the app makes the mobile `tsc` type-check `@smog/auth`'s server sources (`inferAdditionalFields<Auth>()` → `KVNamespace`, `D1Database`, `SendEmail` are unknown there), so the auth client itself is created with the providers (Task 9), which has to solve that first (for example explicit `inferAdditionalFields({ user: … })` fields in `expo.ts`). Jest transforms `.mjs` and `@orpc/*` (oRPC is ESM only).

## Design system

- **2026-09-29 · `@smog/brand` may depend on `@smog/styles` (boundaries change).** Spec §4.1 lists brand → config only, but the icon generator must take the brand green and white from the tokens (nothing written twice). `styles` is a leaf (→ nothing), so no cycle is possible. `@smog/config/boundaries` now allows `@smog/brand` → `@smog/styles`, `@smog/config`. Alternative: repeat the hex values in brand (two sources of truth).
- **2026-09-29 · [ux] Light `focus-ring` is `#C3780F` instead of `#EE971C` (spec §16 deviation, measured).** A focus indicator is non-text UI and needs 3:1 against what surrounds it (WCAG 1.4.11). The brand orange `#EE971C` measures 2.19:1 on `background` `#F7F9F7`, 2.31:1 on `surface` `#FFFFFF`, 2.06:1 on `surface-sunken` and 2.00:1 on `primary-subtle`. `#C3780F` is the same hue and saturation (HSL lightness lowered until every pair passes): 3.30:1 on `background`, 3.49:1 on `surface`, 3.11:1 on `surface-sunken`, 3.02:1 on `primary-subtle`. `accent` stays `#EE971C`, the dark theme is unchanged (`#F5AB45`, 9.69:1 on `background`), and the light `primary` stays `#00805F`. Alternative: keep the orange ring and add a second, dark ring (two tokens for one job).
- **2026-09-29 · Contrast pairs and status text roles (`CONTRAST_PAIRS`) [ux].** Spec §16 lists roles, not pairs, so the pairs the kits may use are fixed in `src/contrast.ts` and tested in both themes, and a test fails when a role is in neither a pair nor `NON_TEXT_ROLES` (`border`, `border-subtle`: decorative; functional edges use `foreground-muted`). The §16 status hues cannot carry small text in light mode (on `background`: `success` 4.14, `warning` 3.44; `primary` is 4.27 on `primary-subtle`; nothing passes on `accent` in both themes), yet Badge/StatusBadge/Field text needs them. So new roles were added, the §16 roles stay unchanged: `*-subtle` tints (light/dark) `success-subtle` `#E3F3EA`/`#123021`, `warning-subtle` `#FBF0DA`/`#33260B`, `danger-subtle` `#FBE9E9`/`#3A1717`; `*-strong` text shades `primary-strong` `#00694E`/`#2BB38A` (5.81:1 on `primary-subtle`, 5.97 on `surface-sunken`), `success-strong` `#166B3A`/`#4CC27E` (5.71 on its tint, 6.57 on `surface`), `warning-strong` `#7A4D06`/`#E9B24A` (6.42, 7.26), `danger-strong` `#A61F1F`/`#F16B6B` (6.32, 7.40; dark 5.37 on its tint); and `accent-foreground` `#17211A`/`#04140E` (7.15 / 9.71 on `accent`). Naming: `*-foreground` is text on the filled role (like `primary-foreground`), `*-strong` is the hue as text on its `*-subtle` tint and on page backgrounds. Body pairs (4.5:1): `foreground`/`foreground-muted` on page backgrounds, `foreground` on every tint, `primary-foreground` on `primary`/`danger`, `accent-foreground` on `accent`, each `*-strong` on its tint and on page backgrounds, `danger` on page backgrounds and `primary-subtle`. UI pairs (3:1): `primary` on page backgrounds and `primary-subtle`, `success`/`warning` on page backgrounds (icons only), `focus-ring` everywhere. - **2026-09-29 · Timestamps are `Date` in TS, integer ms in SQL** (`integer({ mode: "timestamp_ms" })`). - **2026-09-29 · CHECK constraints and partial-index predicates use bare column names.** Drizzle renders `${table.column}` as `"table"."column"`; in SQLite, drizzle-kit changes a CHECK by rebuilding the table as `__new_<table>`, where a qualified name no longer resolves. `packages/db/src/schema/columns.ts` renders `sql.identifier(column.name)` instead (`col()`, `inValues()`, `lengthBetween()`).

- **2026-09-29 · Enum values not named by the spec.** `SPONSORSHIP_EVENT_TYPES` has one type per state-machine event plus `reminder_sent`, `token_issued`, `refund_needed` and `legacy` (migrated rows). `AUDIT_ACTIONS` are dotted `<target>.<verb>` names covering the old `adminLogs` actions (create/update/delete/toggle gestures and categories, approve/reject/force-expire, mark paid, re-edit link, cancel pending payment) plus user management (role, ban, unban, delete, impersonate), `category.reorder`, the maintenance toggle (`maintenance.enable`/`maintenance.disable`, target type `setting`, target id = the KV key) and the sponsorship CSV export (`export.sponsorships_csv`, target type `system`, `target_id` NULL, which is why `audit_log.target_id` is nullable), and `legacy` for unknown migrated shapes (spec §15). ## Auth

- **2026-09-29 · Better Auth plugins:** emailOTP, magicLink, passkey, admin (roles/bans/user list), expo, captcha (Turnstile). The user management UI uses the admin plugin's server API through oRPC.
- **2026-09-29 · Passkeys on mobile: web first.** WebAuthn is not available in React Native; a native passkey module is evaluated in phase 4 and recorded here.
- **2026-09-29 · Better Auth 1.7.6 storage: D1 only, no secondary storage, no cookie cache** (revised in the Task 2 review). Every session read (`getSession`, `requireUser`, `requireAdminUser`) queries D1, so a ban, a revoked session, a role change or a deleted user takes effect on the next request (tests in `packages/auth/test/revocation.test.ts`). Verification values are in D1 too (single-use, consumed there). The first version cached sessions in KV (`secondaryStorage` + `storeSessionInDatabase`); a KV hit was trusted without D1, and revocation deleted KV tokens through a read-modify-write `active-sessions-<userId>` list, which KV's eventual consistency and one-write-per-second-per-key limit can lose, so a revoked or banned session could survive until it expired. **Deviation from spec §6** ("secondary storage in KV for rate-limit counters and verification caches") and from the brief's `createAuth({ kv })`: nothing in auth needs KV now, so the option is gone. Alternatives: a KV adapter that ignores session keys (still no atomic operations for rate limits), or `session.cookieCache` (≤ 60 s, so bans would take up to a minute; not needed, a D1 read by primary key is cheap). Revisit a cookie cache only if session reads show up in latency metrics.
- **2026-09-29 · Password hashing: Better Auth's default scrypt, measured on workerd.** `@better-auth/utils/password` resolves the `workerd` export condition to `node:crypto` `scrypt` (native in workerd with `nodejs_compat`), not the pure-JS `@noble/hashes` fallback. Measured in `packages/auth/test/auth.test.ts` (h): one hash ≈ 86 ms, a whole sign-up request ≈ 100 ms in local workerd. Alternative: PBKDF2 through Web Crypto via `emailAndPassword.password.hash/verify` (a custom hash format for every future credential). Revisit only if production CPU metrics say so.

- **2026-09-29 · Catalogue parity is checked on base keys; plurals follow CLDR per locale.** i18next resolves plurals through `Intl.PluralRules`, and French has a `many` category (for example 1 000 000), so fr plural keys carry `_one`/`_many`/`_other` while nl/en carry `_one`/`_other`. `catalog.test.ts` compares key sets after stripping plural suffixes, requires exactly the locale's CLDR categories on each plural key, and compares `{{placeholders}}` per base key (`count` excluded). A missing key in en/fr is also a type error (`resources` `satisfies Record<Locale, { translation: typeof nl }>`).
- **2026-09-29 · The guest import prompt is composed, not one two-count sentence.** `auth.import.prompt` = "{{items}} importeren?", with `auth.import.favorites` / `auth.import.lists` as plural pieces joined by `formatList` (`Intl.ListFormat`, falling back to the catalogue's `common.and` where Hermes lacks it). This skips zero counts ("12 favorieten importeren?" instead of "12 favorieten en 0 lijsten"). Alternative: one sentence with i18next nesting (`$t(…, {"count": …})`), which cannot drop a zero part.
- **2026-09-29 · Dates are formatted in `Europe/Brussels` with `nl-BE`/`en-BE`/`fr-BE`** (the same Intl locales as `formatMoney`), so the Worker (UTC) and the device render the same day.
