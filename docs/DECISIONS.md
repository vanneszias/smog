# Decisions

Each entry: date · decision · alternatives · why. Newest entries go at the bottom of their section. Business-rule changes are marked **[rule change]**; UX changes **[ux]**; improvements **[improvement]**; dependency additions outside the approved list **[dep]**.

## Process

- **2026-09-29 · Superpowers followed by hand.** The plugin install was not possible in this environment (no `/plugin` command, the org catalog has no match). The skills were cloned from `github.com/obra/superpowers` into the session scratchpad and followed manually: brainstorming → spec → plans → subagent-driven TDD execution → verification → review. Alternative: skip the workflow. Why: the user asked for that workflow.
- **2026-09-29 · Review cadence.** Tasks are sized as cohesive slices (a package or a feature). Each task gets an implementer subagent plus a task reviewer subagent, and a whole-phase review runs between phases. Alternative: one reviewer per micro-step. Why: roughly 100 micro-tasks × 2 reviews would cost more than it catches; phase reviews keep the quality gate.
- **2026-09-29 · Brainstorming questions answered from the prompt.** Every open question was resolved from the user's brief; where the brief was silent the choice below was made.

## Toolchain and versions

- **2026-09-29 · Newest stable version of every package** (user request). A deviation is only allowed for a concrete incompatibility and is listed here.
- **2026-09-29 · TypeScript 7.x** (native `tsc`), per the user's request. TS 7 drops the classic JS compiler API. If a tool needs that API, that tool alone gets a scoped `typescript6` alias (`npm:typescript@6`); none is known yet.
- **2026-09-29 · Keep knip 6** for unused files, exports and dependencies (it uses oxc and does not depend on TypeScript, so it is compatible with TS 7). Dependency direction is enforced by a small Bun script, `scripts/check-boundaries.ts`, against the graph in `@smog/config`. Alternatives: drop knip (loses unused export/file/dependency detection), or dependency-cruiser (covers direction only and parses with the TS API when present). Why: no other tool covers workspace-wide unused code; the script needs no new dependency.
- **2026-09-29 · Vitest 4.x for the Workers pool.** `@cloudflare/vitest-pool-workers@0.22` requires `vitest ^4.1`; Vitest 5 is used nowhere else (pure packages use `bun test`). Revisit when the pool supports 5.
- **2026-09-29 · NativeWind 4.2.7 (stable) with Tailwind 3.4.19 on Expo SDK 57.** Verified in phase 1: `expo export` for iOS and Android compiles the classes (the bundle's injected stylesheet has `text-brand` → `#00805f`, `dark:` as a `prefers-color-scheme` media rule) and the JSX goes through `react-native-css-interop`'s runtime, with Reanimated 4.5.1 / Worklets 0.10.1 and the `babel-preset-expo` + `nativewind/babel` setup. Tailwind 3 lives in the mobile app only; Bun's hoisted linker nests Tailwind 4 under `@tailwindcss/*` for the site. Alternative: NativeWind 5.0.0-rc.0 + `react-native-css` 3.1.0-rc.0 + Tailwind 4 (targets exactly Expo 57, but still a release candidate). Revisit when 5.0 is stable (one Tailwind major across the repo). Not verified here: rendering on a device or simulator (none available in this environment).
- **2026-09-29 · Bun stays at 1.3.11 for now (deviation).** `bun upgrade` to 1.4.2 failed in this environment (the GitHub release download is blocked by the egress proxy, HTTP 403), so `packageManager` pins the installed `bun@1.3.11`. Alternative: pin 1.4.2 without being able to run it (CI would then test a version nobody ran locally). Revisit: bump `packageManager` to the newest 1.x once the toolchain can be upgraded.
- **2026-09-29 · TypeScript 7 `tsc -b` works with shared bases.** Library bases are `composite` and emit declarations only, into `${configDir}/node_modules/.cache/tsc` (TS 7 supports `${configDir}`), so nothing lands next to sources or in `dist/`. `worker.json` adds `${configDir}/worker-configuration.d.ts` (the `wrangler types` output) to `files` instead of depending on `@cloudflare/workers-types`. Alternatives: `--noEmit` per package (breaks project references) or a per-package `outDir` (repeated in every package).
- **2026-09-29 · Root Bun scripts are checked by root Turborepo tasks.** `//#test:scripts` (`bun test scripts`) and `//#check-types:scripts` (`tsc -p scripts`) run beside the package tasks in `bun run test` / `bun run check-types`. They are uncached because root tasks do not hash other workspaces' files (the scripts import `@smog/config`). Package `check-types`/`test` depend on a `transit` node, as the installed Turborepo docs recommend, so they run in parallel but still miss the cache when a dependency changes.

## Architecture

- **2026-09-29 · `@smog/rpc` split from `@smog/api`.** Features need the oRPC base (context, middleware, errors) and `api` composes the features; putting both in one package would create a cycle. `rpc` = base, `api` = composition + client. Alternative: features define their own base (duplicated) or live inside `api` (not modular).
- **2026-09-29 · `@smog/local-store` package** for the on-device guest store with web/native adapters (the brief asked for "one shared local-store abstraction"). Features' `./client` hooks use it when signed out.
- **2026-09-29 · Contract-first oRPC** (`@orpc/contract`), so the mobile bundle only ships contracts and schemas, never server code.
- **2026-09-29 · Jobs package owns message types, producers and schedules; handlers are wired in the site Worker.** This avoids a jobs ↔ features cycle.
- **2026-09-29 · No locale prefix in site URLs.** The language comes from a cookie, then `Accept-Language`, then `nl`. Why: old URLs (`/gestures/…`, `/lists/<token>`) and app links stay valid, and gesture content (the sign videos) is language-neutral. Alternative: `/{nl,en,fr}/…` as in the reference branch (better hreflang, but breaks every old link and deep link).
- **2026-09-29 · Gesture URLs use slugs** (`/gestures/<slug>`); old Convex ids resolve through `gesture.legacy_id` (301 on web, transparent lookup in the app).
- **2026-09-29 · Boundaries graph encodes subpaths.** In `@smog/config/boundaries`, a plain entry (`@smog/db`) allows the package and all subpaths, a subpath entry (`@smog/render/contract`) allows the dependency but only that subpath in imports, and `@smog/feature:*` (optionally `/schema`, `/client`) stands for every package in `FEATURE_PACKAGES`. Every package from spec §4.1 is listed now, before it exists, and a workspace missing from the graph is a violation. `scripts/check-boundaries.ts` checks declared `@smog/*` dependencies and every `@smog/*` import in a workspace's source files (forbidden subpaths and undeclared imports). `@smog/config` may be a devDependency of any package (for the tsconfig bases, spec §4.1 leaves it out of `ui-web`/`ui-native`); as a runtime dependency or import it is still checked. Alternative: Turborepo's experimental `boundaries` (tags only, no subpath rules).
- **2026-09-29 · The boundaries check also covers `optionalDependencies` and mock specifiers.** `vi.mock`/`vi.doMock`/`vi.importActual` and `jest.mock`/`jest.requireActual` (and friends) with an `@smog/*` string count as imports, so a test cannot mock a package its workspace may not use. Closes the phase 1 known gap.
- **2026-09-29 · Site Cloudflare env is chosen at build time with `CLOUDFLARE_ENV`, and deploys go through a guard.** With the Cloudflare Vite plugin, `vite build` flattens one wrangler env into `dist/server/wrangler.json` (`targetEnvironment`) and `wrangler deploy` uses that redirected config, so `--env` does not select bindings: a bare `wrangler deploy` ships whatever env `dist/` was last built for. `vite.config.ts` defaults `CLOUDFLARE_ENV` to `dev` (local dev, test builds, `vite preview`). Deploys only run through `bun -F @smog/site deploy` (`vite build && bun scripts/deploy-guard.ts && wrangler deploy --env $CLOUDFLARE_ENV`). The guard (`apps/site/scripts/deploy-guard.ts`, tested) requires `CLOUDFLARE_ENV` to be `staging` or `production` and the build's `targetEnvironment` to match, so a missing env, `dev`, or a stale build for another env fails before wrangler runs, and wrangler itself refuses an `--env` that differs from the build. `deploy:dry` = `CLOUDFLARE_ENV=staging bun run deploy --dry-run`. `apps/site/turbo.json` hashes `CLOUDFLARE_ENV` for `build` (and caches `.wrangler/deploy/**`, the redirect file), so a dev build is never replayed for staging. CI (`deploy.yml`) must call the `deploy` script, never `wrangler deploy` directly. Alternatives: build the top-level config by default (a deploy then ships without bindings), or `.env.<mode>` files (need `.gitignore` exceptions, same effect).
- **2026-09-29 · `parseWorkerVars` takes `object`.** The generated `Env` is an interface without an index signature, so `Record<string, unknown>` rejected `env` from `cloudflare:workers`; zod validates the shape anyway.
- **2026-09-29 · [dep] oRPC 1.15.4** (`@orpc/contract`, `server`, `client`, `openapi`, `zod`, `tanstack-query`, newest stable, in the root catalog). `@smog/rpc` has four subpaths: `.` (Worker: builders, middleware), `./contract` (`baseContract = oc.errors(ERRORS)`, `ERRORS`, `roleSchema`; only `@orpc/contract` + zod, so contracts in the app bundles never pull `@orpc/server`), `./react` and `./testing` (`makeRpcContext`, `makeSession` for feature tests). `roleSchema` is written out (`["user", "admin"]`) because `@smog/db` (`ROLES`) must not reach the app bundles; a type test keeps it equal to `@smog/auth`'s `Role` and the db enum.
- **2026-09-29 · rpc context shape.** `RpcContext.env` is `WorkerEnv` (`workerEnvSchema` / `parseWorkerEnv` in `@smog/config/env/worker`: vars + secrets; outside `dev` it requires `TURNSTILE_SECRET_KEY`, so `requireTurnstile` cannot fail open in staging/production; Cloudflare's always-pass test secret is fine for a staging without a widget) plus the four rate-limit bindings, typed by a structural `RateLimiter` interface (the Workers `RateLimit` type is global only where `wrangler types` ran). The context has no `user`; `requireUser` / `requireAdmin` add it, so `context.user` is non-null exactly where a guard ran. The site builds the context without I/O (`createRpcContext(request, siteEnv(), { waitUntil })`: `ip` from `cf-connecting-ip`, `unknown` locally; `locale` from the `locale` cookie parsed from the request with `cookie-es` 3.1.1, the parser TanStack Start already uses, then Accept-Language) with `session: null`; the `loadSession` handler interceptor reads the session once with `getSession`, after the `RL_API` limit passed, so a rate-limited request costs no D1 read. Both transports get this order from `rpcHandlerOptions` (`@smog/rpc`).
- **2026-09-29 · rpc errors and middleware.** `ERRORS` carries statuses only (no messages; clients show `@smog/i18n` copy for the code): 409 for `CONFLICT`/`INVALID_STATE`/`GESTURE_UNAVAILABLE`/`PAYMENT_MISMATCH`, 410 `TOKEN_EXPIRED`, 400 `TOKEN_INVALID`, 403 `TURNSTILE_FAILED`/`FORBIDDEN`, 401, 404, 429, and `VALIDATION` 422 with `z.flattenError` data. `mapValidationErrors` (a handler `clientInterceptor`) turns oRPC's `BAD_REQUEST` + `ValidationError` into `VALIDATION`, so input errors are typed. Middleware throws `new ORPCError(code, { status })` instead of `errors.X()`, so it works on any contract; oRPC marks it `defined` when the procedure's contract declares the code (every `baseContract` procedure does). `logErrors` sits on `publicProcedure` and on every procedure of `implementRpc(contract)` (the contract-first implementer features use); ORPC errors below 500 pass silently, anything else is logged as `[rpc:<path>]` and replaced by a bare `INTERNAL_SERVER_ERROR`. Turnstile verification reads `x-turnstile-token` and posts `secret`/`response`/`remoteip` to siteverify. A siteverify network error or non-2xx answer counts as an invalid token (`TURNSTILE_FAILED`, logged; the client retries with a fresh token) instead of a 500. The token travels per call through the typed client context `RpcClientContext` (`{ turnstileToken? }`, `@smog/rpc/contract`), which `ApiClient` and the slice clients of `@smog/rpc/react` carry; `createApiClient`'s link maps it to the `x-turnstile-token` header of that call. - **2026-09-29 · Rate limits: the binding only has 10 s and 60 s periods.** The Workers Rate Limiting `ratelimits` config accepts `period: 10 | 60` only (docs and wrangler's schema), so the old 20/3600 s (sponsor) and 30/900 s (auth) windows cannot be expressed. In staging and production `RL_SPONSOR` and `RL_AUTH` are 5/60 s: the old count spread over one minute rounds to 1 and 2, which would block a normal multi-step flow (send code + verify + a typo; logo upload + checkout), so the floor is 5 per minute. Long-run this is looser (auth 75/15 min instead of 30; sponsor 300/h instead of 20). Better Auth's own limiter is only a per-isolate memory counter outside dev (see Auth), not a real per-IP limit. `RL_API` 300/60 s and `RL_ANALYTICS` 120/60 s are exact. `dev` allows 1000/60 s on all four: miniflare enforces the bindings and every local request shares the `unknown` IP, so the old values would lock out a developer or the e2e suite. Namespace ids are unique per binding and env (dev 1001–1004, staging 2001–2004, production 3001–3004; tests 9003). Where each applies: `RL_API` per IP on every request of both transports (`limitRequests("RL_API", "api")`, a handler interceptor that runs before the session lookup and throws `RATE_LIMITED` with `defined: true`, like the old `/rpc/*` limit); `RL_AUTH` per IP on `POST /api/auth/*` except `/sign-out` and `/get-session`, which only act on the caller's own cookie (429 `{ "code": "RATE_LIMITED" }`, `retry-after: 60`); `rateLimit(binding)` per procedure keyed `<ip>:<path>` for `RL_SPONSOR` (and `RL_ANALYTICS`) in later phases. Alternatives: a KV/D1 counter for the long windows (writes our own limiter, KV is not atomic), or 1–2/60 s (breaks flows). Revisit if abuse shows up.

- **2026-09-29 · `@smog/brand` may depend on `@smog/styles` (boundaries change).** Spec §4.1 lists brand → config only, but the icon generator must take the brand green and white from the tokens (nothing written twice). `styles` is a leaf (→ nothing), so no cycle is possible. `@smog/config/boundaries` now allows `@smog/brand` → `@smog/styles`, `@smog/config`. - **2026-09-29 · [ux] Light `focus-ring` is `#C3780F` instead of `#EE971C` (spec §16 deviation, measured).** A focus indicator is non-text UI and needs 3:1 against what surrounds it (WCAG 1.4.11). The brand orange `#EE971C` measures 2.19:1 on `background` `#F7F9F7`, 2.31:1 on `surface` `#FFFFFF`, 2.06:1 on `surface-sunken` and 2.00:1 on `primary-subtle`. `#C3780F` is the same hue and saturation (HSL lightness lowered until every pair passes): 3.30:1 on `background`, 3.49:1 on `surface`, 3.11:1 on `surface-sunken`, 3.02:1 on `primary-subtle`. `accent` stays `#EE971C`, the dark theme is unchanged (`#F5AB45`, 9.69:1 on `background`), and the light `primary` stays `#00805F`. - **2026-09-29 · Contrast pairs and status text roles (`CONTRAST_PAIRS`) [ux].** Spec §16 lists roles, not pairs, so the pairs the kits may use are fixed in `src/contrast.ts` and tested in both themes, and a test fails when a role is in neither a pair nor `NON_TEXT_ROLES` (`border`, `border-subtle`: decorative; functional edges use `foreground-muted`). The §16 status hues cannot carry small text in light mode (on `background`: `success` 4.14, `warning` 3.44; `primary` is 4.27 on `primary-subtle`; nothing passes on `accent` in both themes), yet Badge/StatusBadge/Field text needs them. Body pairs (4.5:1): `foreground`/`foreground-muted` on page backgrounds, `foreground` on every tint, `primary-foreground` on `primary`/`danger`, `accent-foreground` on `accent`, each `*-strong` on its tint and on page backgrounds, `danger` on page backgrounds and `primary-subtle`. - **2026-09-29 · Timestamps are `Date` in TS, integer ms in SQL** (`integer({ mode: "timestamp_ms" })`). - **2026-09-29 · CHECK constraints and partial-index predicates use bare column names.** Drizzle renders `${table.column}` as `"table"."column"`; in SQLite, drizzle-kit changes a CHECK by rebuilding the table as `__new_<table>`, where a qualified name no longer resolves. `packages/db/src/schema/columns.ts` renders `sql.identifier(column.name)` instead (`col()`, `inValues()`, `lengthBetween()`).

- **2026-09-29 · Enum values not named by the spec.** `SPONSORSHIP_EVENT_TYPES` has one type per state-machine event plus `reminder_sent`, `token_issued`, `refund_needed` and `legacy` (migrated rows). `AUDIT_ACTIONS` are dotted `<target>.<verb>` names covering the old `adminLogs` actions (create/update/delete/toggle gestures and categories, approve/reject/force-expire, mark paid, re-edit link, cancel pending payment) plus user management (role, ban, unban, delete, impersonate), `category.reorder`, the maintenance toggle (`maintenance.enable`/`maintenance.disable`, target type `setting`, target id = the KV key) and the sponsorship CSV export (`export.sponsorships_csv`, target type `system`, `target_id` NULL, which is why `audit_log.target_id` is nullable), and `legacy` for unknown migrated shapes (spec §15). ## Auth

- **2026-09-29 · Better Auth plugins:** emailOTP, magicLink, passkey, admin (roles/bans/user list), expo, captcha (Turnstile). The user management UI uses the admin plugin's server API through oRPC.
- **2026-09-29 · Passkeys on mobile: web first.** WebAuthn is not available in React Native; a native passkey module is evaluated in phase 4 and recorded here.
- **2026-09-29 · Better Auth 1.7.6 storage: D1 only, no secondary storage, no cookie cache** (revised in the Task 2 review). Every session read (`getSession`, `requireUser`, `requireAdminUser`) queries D1, so a ban, a revoked session, a role change or a deleted user takes effect on the next request (tests in `packages/auth/test/revocation.test.ts`). Verification values are in D1 too (single-use, consumed there). The first version cached sessions in KV (`secondaryStorage` + `storeSessionInDatabase`); a KV hit was trusted without D1, and revocation deleted KV tokens through a read-modify-write `active-sessions-<userId>` list, which KV's eventual consistency and one-write-per-second-per-key limit can lose, so a revoked or banned session could survive until it expired. **Deviation from spec §6** ("secondary storage in KV for rate-limit counters and verification caches") and from the brief's `createAuth({ kv })`: nothing in auth needs KV now, so the option is gone. Alternatives: a KV adapter that ignores session keys (still no atomic operations for rate limits), or `session.cookieCache` (≤ 60 s, so bans would take up to a minute; not needed, a D1 read by primary key is cheap). Revisit a cookie cache only if session reads show up in latency metrics.
- **2026-09-29 · Password hashing: Better Auth's default scrypt, measured on workerd.** `@better-auth/utils/password` resolves the `workerd` export condition to `node:crypto` `scrypt` (native in workerd with `nodejs_compat`), not the pure-JS `@noble/hashes` fallback. Measured in `packages/auth/test/auth.test.ts` (h): one hash ≈ 86 ms, a whole sign-up request ≈ 100 ms in local workerd. That fits Workers Paid (30 s CPU default; the Email Service needs Paid anyway) but not the Free plan's 10 ms. Alternative: PBKDF2 through Web Crypto via `emailAndPassword.password.hash/verify` (a custom hash format for every future credential). Revisit only if production CPU metrics say so.
- **2026-09-29 · Better Auth schema reconciled with its CLI; no migration.** `@better-auth/cli` is deprecated; the CLI is now the `auth` package (`bunx auth@1.7.6 generate --config <file>`). Its Drizzle SQLite output for our config (admin, passkey, emailOTP, magicLink, expo, captcha, `locale`/`legacyId` fields) has exactly our columns, types and FKs. The only differences are the deliberate ones: `role NOT NULL DEFAULT 'user'` + CHECK (the CLI makes it nullable; `admin({ defaultRole: "user" })` always writes it, asserted by a sign-up test), `legacy_id` unique, TS-side instead of SQL `created_at`/`updated_at` defaults, snake_case index names (`session_user_id_idx` vs the CLI's `session_userId_idx`) and our extra indexes.
- **2026-09-29 · Auth config details.** Cookie prefix `smog` (`smog.session_token`, `__Secure-smog.session_token` outside dev, where `useSecureCookies` is on); the Expo client uses the same prefix. Apple adds `https://appleid.apple.com` to `trustedOrigins` when configured (its form_post callback). The Expo client omits the passkey plugin (web first, see above). - **2026-09-29 · The dev seed gives `admin@smog.test` a dev-only password (`smog-dev-admin`).** `scripts/seed.ts` hashes it with Better Auth's scrypt format (`<hex salt>:<hex key>`, N=16384, r=16, p=1, 64-byte key, NFKC) and a fixed salt, so `seed/dev.sql` stays deterministic. Alternative: OTP/magic link only (slower manual testing and e2e).
- **2026-09-29 · CSRF defence in depth on `/api/rpc` and `/api/openapi`: an origin check before anything else.** SameSite=Lax on the session cookie stops cross-site POSTs, but not a same-site, cross-origin page (another Worker on the same `workers.dev` subdomain, a sibling subdomain, another `localhost` port), and oRPC accepts CORS-simple bodies (`multipart/form-data` with a `data` field, urlencoded, `text/plain`), so a plain HTML form was a valid rpc call. `checkOrigin` (`@smog/rpc`, first in `rpcHandlerOptions`, so both transports get it before `RL_API` and the session read) answers a non-GET/HEAD request with a defined `FORBIDDEN` (403) when `Sec-Fetch-Site` is present and is neither `same-origin` nor `none`, or when `Origin` is present and is not `new URL(SITE_URL).origin` (in `dev`, any `http://localhost:<port>` is also accepted, for the Expo web and tooling ports). Consequence: each environment's `SITE_URL` must be the origin browsers use (as for Better Auth's `trustedOrigins`). Alternatives: oRPC's `SimpleCsrfProtectionHandlerPlugin` + link plugin (a custom header forcing a preflight; needs a Scalar exemption and client wiring in both apps), rejecting non-JSON bodies (blocks the phase 7 logo upload). Why: Fetch Metadata plus Origin covers every current browser, needs no client change and keeps the native app working.

- **2026-09-29 · Ranking details beyond spec §7.1.** Queries and field values are compared as their letter/digit tokens joined by one space (`normalizeQuery`: `normalizeText`, then split like FTS5 `unicode61`), so a word boundary is "start or after a space" and `"hond!"` equals `hond`. A query with no tokens (only spaces or punctuation, e.g. `"*-(`) is an empty query: the browse list. A multi-word query that matches no single value as a whole (words in different fields or out of order, which FTS5's `AND` finds) still matches at the word-boundary tier, weighted by the field of its weakest word; without it, such FTS hits would be dropped. The typo tier compares name, keywords and categories only (the spec's projection; descriptions would add noise), with the optimal-string-alignment Damerau–Levenshtein distance. Ties after the name use the id, so the order is total. `search` keeps the best 200 FTS candidates by `bm25` (column weights 10/5/3/1, like the field weights); `total` counts direct matches (≤ 200) plus typo matches; the browse list has `score` 0 and null `matchedField`/`matchType`. - **2026-09-29 · `catalog:version`: a random id per bump, a fixed sentinel when missing, never written by reads.** `bumpCatalogVersion(kv)` writes `newId()` and is the only KV write; KV has no atomic increment, so two concurrent counter bumps could both write n + 1 and leave an isolate on a projection it built between them. A missing key (a new namespace) reads as `INITIAL_CATALOG_VERSION` (`"initial"`) with no write, so the first searches after a deploy never hit KV's one-write-per-second-per-key limit. The typo tier is best effort: if KV or the projection load fails, `searchGestures` logs `[gestures] Failed to load the typo tier, …` and answers with the direct matches. Only the resolved projection (plain data) is cached per isolate; no in-flight promise is shared, because in workerd awaiting a promise whose I/O belongs to another request can hang or throw once that request ends. Concurrent cold misses therefore each load the catalogue, which is cheap at its size. Other isolates see a bump within KV's propagation delay (up to a minute); only typo matches for the change are delayed, because the direct tier reads D1. - **2026-09-29 · [rule change] At most 100 lists per account and 500 gestures per list.** `create` and `addItem` answer `INVALID_STATE` at `LISTS_MAX` / `LIST_ITEMS_MAX` (in `@smog/lists/schema`). - **2026-09-29 · Positions, unpublished gestures and concurrency.** An add is one `INSERT … SELECT coalesce(max(position) + 1, 0) … ON CONFLICT DO NOTHING` (plus the `updated_at` bump) in one batch, so concurrent adds get distinct dense positions and a repeated add is a no-op (`{ added: false }`). A remove shifts the rows after it down and deletes the row in the same batch (`{ removed }`). The owner's add reads ownership, publication and presence in one query, so it is one read plus one batch. A reorder must be exactly the list's **published** gestures (what the owner sees; missing, extra or duplicate ids → `INVALID_STATE`); unpublished ones keep their relative order after them, and only the payload's and the hidden rows are rewritten, so an add landing between the read and the write keeps its `max + 1` place. A deleted gesture's `ON DELETE CASCADE` leaves a gap in the positions until the next reorder (the order stays correct). A full re-densify with `UPDATE … SET position = (correlated count over list_item)` was rejected: SQLite gives no snapshot guarantee for a subquery over the table being updated.
- **2026-09-29 · Share links and the shared view.** `share.create` inserts with `ON CONFLICT DO NOTHING` (the partial unique index `list_share_active_role_uq`) and reads the active link in the same batch, so concurrent creates agree on one token; `share.revoke` sets `revoked_at` (a no-op without an active link); regenerating is `useShareLinks().regenerate(role)` = revoke + create. `shared.get` is public and batches the head (list, role, owner name) with the items resolved from the token, so an unknown or revoked token (or a list id tried as a token) is `NOT_FOUND`. `ownerName` is `user.name` trimmed, else `lists.ownerFallback` in the request locale; the email and ids are never returned. `shared.addItem/removeItem` check the session first (`UNAUTHORIZED`), then the token (`NOT_FOUND`), then the role (`FORBIDDEN` for a view link); an editor's add records `added_by` = the editor. `url` is `SITE_URL` (trailing slashes dropped) + `/lists/` + token. - **2026-09-29 · Lists hooks.** `useLists()` (`{ lists, status, error, create }`), `useList(id)` (`{ list, status, notFound, error, update, remove, addItem, removeItem, reorder }`), `useShareLinks(id)` (`{ requiresAccount: true }` for guests and `loc_` lists, else `{ links, status, create, revoke, regenerate }`) and `useSharedList(token)` (`{ data, status, notFound, canEdit, requiresSignIn, addItem, removeItem }`).
